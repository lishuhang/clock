## 4. 自动保活完整流程

### 4.1 用户首次配置

1. 用户在 squido.ai 注册账号, 用 get cookies.txt 插件导出 cookies
2. 打开 https://ai-image.lishuhang.workers.dev
3. 点 ⚙ 设置, 粘贴 cookies.txt 整段
4. 点保存 → 前端:
   - 解析 cookies, 提取 `__Secure-better-auth.session_token`
   - 解码 `session_data` JWT 拿 `expiresAt` (7 天后)
   - 存 localStorage
   - 上传到 KV (用本地随机 clientId 区分用户)
   - 触发首次保活检查 (此时距过期 7 天, 不触发续期)

### 4.2 日常使用 (用户每周用一次)

1. 用户打开 worker, 输入 prompt, 点生成
2. 前端 `apiFetch` 调 `/api/generate/image`
3. Worker 代理到 squido, 返回结果
4. 前端检查 `X-Squido-Set-Cookie`:
   - 如果有 (BetterAuth 续期了), 更新 localStorage + KV
   - 如果没有 (session 还新), 正常返回
5. 前端每小时定时检查 `getTokensNeedingKeepalive()`:
   - 如果距过期 < 6.5 天, 调 `/api/check-session` 触发续期
   - 捕获 Set-Cookie 更新

### 4.3 用户长期不用 (浏览器关闭)

1. Cron Trigger 每天 GMT+8 03:00 触发
2. `keepaliveAllStoredTokens()` 遍历 KV 所有 client
3. 对距过期 < 6.5 天的 token, 调 squido `/api/get-user-info`
4. 捕获 Set-Cookie 更新 KV
5. 用户下次打开前端, 从 KV 加载最新 token

**效果**: 只要用户每 7 天内打开过一次前端 (上传 token 到 KV), 后续即使浏览器关闭, cron 也能自动保活。**配置一次永久使用**。

## 5. 突出问题与避坑 (给下个 agent)

### 5.1 ⚠️ BetterAuth 续期是滑动的, 不是每次都续

**问题**: BetterAuth 只在 session 真正接近过期时 (通常 < 1 天) 才发 Set-Cookie。大多数 API 调用不会触发续期。

**避免**: 不要期望每次调 squido API 都能拿到 Set-Cookie。`refreshed:0` 是正常的, 只要 `lastKeepaliveAt` 更新了就说明保活调用成功。

### 5.2 ⚠️ Cloudflare KV 写入有最终一致性延迟

**问题**: KV 写入后, 全球边缘节点同步可能需要 ~60 秒。立即读取可能拿到旧值。

**避免**: 前端上传 token 后, 不要立即从 KV 加载期望拿到新值。本地 localStorage 是 source of truth, KV 只是 cron 的备份。

### 5.3 ⚠️ Cron Trigger 每天只触发一次

**问题**: 当前配置 `0 19 * * *` (UTC 19:00 = GMT+8 03:00) 每天一次。如果用户 session 在 03:01 过期, cron 还要等 24 小时才触发。

**避免**: 如果要更频繁, 可加第二个 cron (如 `0 7,19 * * *` 每天 2 次), 但要注意 Cloudflare Workers 免费版 cron 限额 (每天最多 5 个 cron 触发)。

### 5.4 ⚠️ KV 中 token 永久保留 (无 TTL)

**问题**: 用户清空 localStorage 后, KV 中的 token 仍会保留, cron 会继续尝试保活已废弃的 token。

**避免**: 后续可加 KV TTL (写时 `put(key, val, {expirationTtl: 86400 * 30})` 30 天后自动清理), 或加 `/api/keepalive-delete` 端点让用户主动删除。

### 5.5 ⚠️ clientId 用 localStorage 随机生成, 跨设备不同

**问题**: 用户在不同设备打开 worker, localStorage 的 clientId 不同, 会上传到不同 KV key, cron 会重复保活同一账号。

**避免**: 后续可让用户配置一个自定义 clientId (如邮箱), 跨设备同步。当前实现是简化版, 假设单设备使用。

### 5.6 ⚠️ `/admin/keepalive-now` 无鉴权

**问题**: 任何人都可以 POST `/admin/keepalive-now` 触发保活, 可能被滥用刷 squido API。

**避免**: 后续可加一个简单的 admin token (在 wrangler.toml secrets 配置), 验证 `Authorization` header。当前实现假设 worker URL 不公开。
