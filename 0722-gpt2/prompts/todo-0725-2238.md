### 3.1 ❌ 无法自动注册 squido 账号

**5 种 Playwright 方案全部失败**:
1. 纯 headless Chrome → Turnstile 不渲染 iframe
2. stealth init script (mask webdriver) → 不渲染
3. Firefox headless → 不渲染
4. `--headed` + Xvfb (Playwright) → Chrome 启动失败 (`Missing X server` 即使 DISPLAY=:99)
5. `agent-browser --headed` (自带 Xvfb) → Turnstile 加载 script 但不渲染 iframe
6. `playwright-extra + puppeteer-extra-plugin-stealth` → 不渲染
7. **手动调 `window.turnstile.render()`** → 也不渲染 iframe

**根本原因**: Cloudflare Turnstile 在 2025+ 检测能力极强, 即使 stealth 伪装了 `navigator.webdriver=false`, 仍能通过其他指纹 (Canvas 指纹、WebGL 指纹、内存、CPU 核心数、字体列表、屏幕分辨率等) 检测到 headless 环境, 直接拒绝渲染 challenge iframe。

**结论**: 在我们的容器化环境里, **squido 自动注册彻底不可行**。

## 5. 突出问题与避坑 (给下个 agent)

### 5.1 ⚠️ Cloudflare Turnstile 在 headless 容器中无法绕过

**问题**: 即使使用最先进的 stealth 插件 (puppeteer-extra-plugin-stealth), Turnstile 仍能检测 headless 并拒绝渲染 iframe。

**已尝试**:
- mask `navigator.webdriver` → 无效
- `--disable-blink-features=AutomationControlled` → 无效
- Firefox 替代 Chrome → 无效
- Xvfb 虚拟显示 → 无效 (且 Xvfb 在容器中启动困难, 需要 `setsid` 守护 + `/tmp/.X11-unix` 权限)
- `playwright-extra + stealth` → 无效
- 手动调 `window.turnstile.render()` → 不渲染

**避免**: 不要再花时间在 squido Turnstile 自动绕过上。如果用户坚持自动化, 唯一可行路径是**第三方 CAPTCHA 解决服务** (2Captcha 等, ~¥0.05/次) 或**用户手工预注册**。

### 5.2 ⚠️ Xvfb 在容器中启动困难

**问题**: 直接 `Xvfb :99 &` 启动后, Chrome 仍报 "Missing X server"。原因:
- `/tmp/.X11-unix` 目录默认不存在, 需 `mkdir -p /tmp/.X11-unix && chmod 1777 /tmp/.X11-unix`
- 没有 `xauth` 包, Xvfb 拒绝非 root 客户端
- Chrome 启动时需要 dbus socket (`/run/dbus/system_bus_socket`), 容器中也没有

**避免**: 用 `agent-browser --headed` 自动管理 Xvfb, 不要手动启动。

### 5.3 ⚠️ sq-v1.0 部署覆盖了 kd-v2.3

**问题**: sq-v1.0 部署到 `ai-image` worker (与 kd-v2.3 同名), 覆盖了 kd-v2.3 的部署。但 kd-v2.3 的源文件 `gpt2-worker-kd-v2.3.js` 仍在 GitHub repo 中, 不会丢失。

**避免**: 如果用户想回滚 kd-v2.3, `cd 0722-gpt2/.deploy && cp ../gpt2-worker-kd-v2.3.js worker.js && npx wrangler deploy` 即可。

### 5.4 ⚠️ Squido API 的 `/api/generate/Image` 走 squido 自身代理, 不是直接 api.squido.ai

**问题**: 一开始误以为 submit 是直接 POST `api.squido.ai/v1/image`, 实际是 POST `squido.ai/api/generate/Image` (走 squido 自己的代理层)。

**避免**: worker 的 `handleProxy` 必须区分:
- `POST /api/generate/Image` → 转发到 `https://squido.ai/api/generate/Image` (带 Cookie)
- `GET /api/generate/{taskId}` → 转发到 `https://api.squido.ai/v1/image/{taskId}` (无需 Cookie, 但加上更安全)

### 5.5 ⚠️ Squido ev (submit body) 字段名特殊

**问题**: 字段名不是 OpenAI 标准的 `size` 而是 `resolution` + `ratio` 分开。`resolution` 是 "1K"/"2K"/"4K", `ratio` 是 "16:9"/"1:1"/"9:16" 等。

**避免**: 不要把 OpenAI API 的 `size: "1792x1024"` 直接传给 squido, 必须拆成 `resolution: "1K"` + `ratio: "16:9"`。

### 5.6 ⚠️ `wrangler deploy` 解析 HTML 字符串内的 JS 重复声明

**问题**: sq-v1.0.js 顶部 `const UPSTREAM = {...}` 与 HTML_CONTENT 模板字符串内 `<script>` 中的 `const UPSTREAM_BASE = '...'` 在 wrangler 解析时报 "duplicate declaration"。

**修复**: 把 HTML 内的 const 改名 (UPSTREAM_BASE 只在前端 script 内用, 不与顶层冲突)。但 wrangler 4.x 似乎会扫描整个文件, 即使在字符串内。本次部署已删除顶层重复的 `const UPSTREAM` (用顶层的那个), 部署成功。

**避免**: 不要在 worker 顶层和 HTML 模板字符串内 `<script>` 中用相同的 const 名称。
