## 1. Cookies 有效期分析 (回答用户问题)

### 1.1 用户提供的 cookies 时间信息

| 字段 | 值 | 含义 |
|------|-----|------|
| `__Secure-better-auth.session_token` cookie 过期 | `1785631949` (epoch) = **2026-08-04 17:32 UTC** | cookie 本身的 max-age, 浏览器会自动删除 |
| `__Secure-better-auth.session_data` cookie 过期 | `1785027449` (epoch) = **2026-07-28 17:37 UTC** | 短期 cookie, 用于 BetterAuth 滚动续期 |
| 内部 session expiresAt (在 session_data 解码后) | `2026-08-02T00:52:15.226Z` | 实际 session 失效时间 |
| 用户 createdAt | `2026-07-26T00:52:14` UTC = **2026-07-26 08:52 GMT+8** | 用户注册时间 (几小时前) |

### 1.2 Cookies 有效期结论

- **session_data cookie**: 2 天后过期 (2026-07-28)
- **session_token cookie**: 9 天后过期 (2026-08-04)
- **BetterAuth session**: 7 天后过期 (2026-08-02)
- **结论**: 用户**每 7 天需要重新登录一次** squido.ai 并更新 worker 配置

### 1.3 "用户无感知, 配置一次即可无限制使用" 方案

**方案 1 (短期, 部分有效)**: Worker 捕获 Set-Cookie 自动续期
- BetterAuth 在每次 API 调用时会返回 `Set-Cookie: __Secure-better-auth.session_data=...` 续期 session_data
- Worker 已经实现 `X-Squido-Set-Cookie` response header 捕获
- 前端可以读取这个 header, 更新本地存储的 cookie
- **效果**: session_data 自动续期, 用户不需要每周更新
- **限制**: session_token 仍然 9 天后过期, 用户最长 9 天必须重新登录一次

**方案 2 (中期, 需要重新登录)**: 多账号轮换
- 配置 5-10 个 squido 账号
- 每个账号 7-9 天过期, 但只要不同时过期, 总有可用账号
- 用户每周只需更新 1-2 个过期账号
- 当前 sq-v1.0 已支持多账号轮换

**方案 3 (长期, 完全自动)**: 自动重新注册
- 需要绕过 Cloudflare Turnstile (实测不可行, 见 todo-0725-2238)
- 或者用第三方 CAPTCHA 服务 (2Captcha, ¥0.05/次)
- 不推荐, 工作量大且持续成本

**推荐**: 方案 1 + 方案 2 组合 — Worker 自动续 session_data, 用户每周更新一个新账号作为轮换补充。每周维护成本 < 5 分钟。

## 2. sq-v1.0 修复内容

### 2.1 SESSION_HEADER bug 修复

**Bug**: 前端 `<script>` 内引用 `SESSION_HEADER` (Worker 顶层 const), 浏览器里未定义, 报 `SESSION_HEADER is not defined`。

**修复**: 前端定义自己的常量 `SQ_COOKIE_HEADER = 'X-Squido-Cookie'`, 不再依赖 Worker 顶层。

### 2.2 Cookie 格式改进

**旧**: 用户填 `eyJ...` (session_data 值), worker 用 `__session=` 拼接 (错误)
**新**: 用户可粘整段 cookies.txt (Netscape 格式), 前端自动提取 `__Secure-better-auth.session_token`, 转成 `__Secure-better-auth.session_token=VALUE` 格式发给 worker

支持多种输入格式:
- 整段 cookies.txt (推荐, 浏览器插件导出)
- 单行 `__Secure-better-auth.session_token=VALUE`
- 单行纯 VALUE (自动加前缀)

多账号用空行分隔。

### 2.3 API URL 修正

**旧**: `/api/generate/Image` (大写 Image) → 404
**新**: `/api/generate/image` (小写 image) → 200 + `{taskId}`

(从 JS chunk 提取: `s.B.Image = "image"` 枚举值)

### 2.4 浏览器 header 增强 (绕 Cloudflare 1010)

Worker fetch 默认 UA 是 `Cloudflare-Workers`, squido 的 Cloudflare 防火墙识别后返回 1010。
增加完整浏览器 header:
- `User-Agent` (真实 Chrome)
- `Accept-Language`, `Accept-Encoding`
- `sec-ch-ua`, `sec-ch-ua-mobile`, `sec-ch-ua-platform`
- `Sec-Fetch-Dest`, `Sec-Fetch-Mode`, `Sec-Fetch-Site`

### 2.5 新增 daily-checkin 端点

`POST /api/daily-checkin` → 代理到 `https://squido.ai/api/get-credits-by-sign-in`

前端新增 "🎁 每日签到" 按钮, 一键为所有配置的账号领取每日 7 credits。

### 2.6 Set-Cookie 捕获

Worker 捕获上游 `Set-Cookie` 响应头, 通过 `X-Squido-Set-Cookie` 返回给前端。前端可读这个 header 自动续期 session_data (实现 "无感知" 续期, 待前端代码实现)。

### 2.7 Token 有效性标记

Worker 通过 `X-Squido-Token-Valid` response header 标记 token 是否仍有效 (401 = 失效)。前端可据此自动清理过期 token (待前端代码实现)。

## 6. 突出问题与避坑 (给下个 agent)

### 6.1 ⚠️ squido 用 BetterAuth 不是 Clerk

**问题**: 之前调研时看到 Clerk publishableKey 在 JS chunks 里, 误以为 squido 用 Clerk。实际认证 cookie 名是 `__Secure-better-auth.session_token` — BetterAuth 标准。

**避免**: 后续 agent 不要再以 Clerk 模式调 squido auth。Clerk 集成可能只用于 "Continue with Google" OAuth 按钮, 实际 session 管理用 BetterAuth。

### 6.2 ⚠️ Squido submit URL 是小写 `/api/generate/image`

**问题**: JS 代码 `s.B.Image` 枚举值是 `"image"` (小写), 但我之前以为是 `"Image"` (大写), 导致 404。

**避免**: 后续 agent 看 JS chunks 的 enum 值时, 注意大小写。

### 6.3 ⚠️ Cloudflare 1010 错误 (Worker fetch squido.ai)

**问题**: Worker fetch squido.ai 默认 UA 是 `Cloudflare-Workers`, squido 的 Cloudflare 防火墙识别后返回 1010。

**修复**: 在 upstreamInit.headers 中加入完整浏览器 header (UA + sec-ch-ua + Sec-Fetch-* + Accept-Language 等)。

**避免**: 后续如果 worker proxy 其他 Cloudflare 保护的站点, 都要加完整浏览器 header。

### 6.4 ⚠️ Python urllib 测试不可靠

**问题**: Python urllib 调 worker 时返回 1010, 但 curl 调同一 worker 时返回 200。差异在 HTTP/2 vs HTTP/1.1, urllib 默认 HTTP/1.1 可能被 CF 边缘节点不同处理。

**避免**: 测试 worker 端点时用 curl, 不要用 Python urllib。

### 6.5 ⚠️ 用户 credits=0 的根因未明

**问题**: 用户 squido 账号已签到但 credits=0, daily_free_credits=0。可能原因:
- squido 新账号当天不发 credits (第二天才发)
- IP 风控 (用户 IP `14.19.17.134` 可能被识别)
- squido 后端 bug

**避免**: 后续 agent 应该:
1. 让用户在 squido.ai 网页上点 "Claim Reward" 按钮看实际效果
2. 或让用户注册新账号测试
3. 或等 24 小时看 credits 是否自动到账

### 6.6 ⚠️ Cloudflare Worker fetch 不能直接传 Cookie header

**问题**: Worker fetch 默认会过滤某些 header (如 Cookie)。需要显式设置 `upstreamInit.headers['Cookie'] = cookieHeader` 才能转发。

**避免**: 后续 agent 写 worker proxy 时, 永远显式设置 Cookie, 不要假设会自动转发。
