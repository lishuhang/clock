### 4.4 认证机制 — **无法避免注册** ⚠️

**第一步: Clerk 邮箱 OTP**

- 端点: `POST /api/auth/send-email-otp`
- 端点: `/sign-in/email` (邮箱+密码) 或 `/sign-in/email-otp` (邮箱+OTP)
- 端点: `/sign-up/email` (注册)
- 第三方库: **Clerk** (publishable key 在 JS 中, 标准前后端分离模式)

**第二步: Cloudflare Turnstile CAPTCHA**

直接 POST `/api/auth/send-email-otp` `{"email": "..."}` 返回:
```json
{"success": false, "error": "token is required"}
```

JS chunks 中明确含 `cf-turnstile` 组件 + `https://challenges.cloudflare.com/turnstile/v0/api.js` 引用, "token" 即 Turnstile 响应令牌。

**邮箱域名黑名单 (实测)**:

| 邮箱后缀 | send-email-otp 响应 |
|---------|---------------------|
| gmail.com / outlook.com | `{"success": false, "error": "token is required"}` ← 通过邮箱格式校验, 但需 Turnstile |
| web-library.net (mail.tm 域名) | 同上 ← **临时邮箱可用** |
| 1secmail.com | 同上 ← **临时邮箱可用** |
| mailinator.com | `{"success": false, "error": "Invalid email address"}` ← 被屏蔽 |
| guerrillamail.com | 同上 ← 被屏蔽 |
| yopmail.com | 同上 ← 被屏蔽 |
| temp-mail.org | 同上 ← 被屏蔽 |

→ mail.tm 域名 `web-library.net` 通过校验, **临时邮箱技术可用**

### 4.5 API 端点清单 (从 JS chunks 提取)

```
POST   /api/auth/send-email-otp        发送 OTP (需 Turnstile token)
*      /api/auth                        Clerk 回调
POST   /api/get-credits-by-sign-in      查询当前用户额度 (需登录)
POST   /api/get-user-info                查询用户信息 (需登录)
POST   /api/generate/                    生成图片 (需登录, 内部代理 api.squido.ai)
POST   https://api.squido.ai/v1/image/   真实生图 API (需 Bearer token)
POST   https://api.squido.ai/upload      上传参考图 (需 Bearer token)
```

### 4.6 实际 API 调用流程 (推测)

1. 浏览器加载 `/sign-in/email-otp`, 渲染 Turnstile widget
2. 用户通过 Turnstile → 前端拿到 `cf-turnstile-response` token
3. 前端 POST `/api/auth/send-email-otp` `{email, token}` → 服务端验证 Turnstile → 发送 OTP 邮件
4. 用户输入 OTP → Clerk 验证 → 颁发 `__session` cookie (JWT)
5. 前端 POST `/api/generate/` (带 cookie) → 后端代理 `api.squido.ai/v1/image/`
6. 后端扣减 credits, 返回图片 URL

## 5. sq-v1.0 重构路径 — 三选一 (等用户决策)

### 路径 A: 手工预注册 + token 轮换 (推荐起步)

**做法**:
1. 用 mail.tm 注册 5-10 个临时邮箱 (web-library.net 域名)
2. 浏览器手动通过 Turnstile, 完成每个邮箱的 squido 注册流程
3. 从浏览器 devtools 拷贝每个账号的 `__session` cookie (Clerk JWT)
4. sq-v1.0 worker 内置 token 数组, 轮换使用, 每天 GMT+8 0点重置日额计数
5. token 过期 (~30天) 后手动刷新

**优点**:
- 实现简单 (1-2 小时编码)
- 不依赖 CAPTCHA 破解服务
- 不依赖临时邮箱 API

**缺点**:
- 单账号仅 2 张/日, 10 个账号 = 20 张/日
- token 过期需手动续期
- 账号被风控可能被封

**实现要点**:

### 路径 B: 自动化批量注册 (高级, 工作量大)

**做法**:
1. 用 Playwright headless 浏览器加载 `/sign-in/email-otp`
2. 等待 Turnstile widget 自动通过 (Turnstile 在浏览器中可能 invisible 通过)
3. 调用 mail.tm API 创建临时邮箱, POST OTP 请求
4. mail.tm API 轮询收件箱, 提取 OTP
5. 提交 OTP, 拿到 Clerk session cookie
6. 把 token 存到 CF KV 或 D1
7. 定时 (cron trigger) 检查 token 有效性, 过期就重新注册

**优点**:
- 完全自动, 理论上可无限扩展账号数
- 类似马良版本的"批量注册"思路

**缺点**:
- **Cloudflare Turnstile 在 headless 中可能不通过** — Turnstile 专门检测 headless, 可能需要 puppeteer-stealth 等额外配置
- **mail.tm 速率限制** — 免费档每分钟 ~8 请求
- **实现工作量**: 1-2 天编码 + 持续维护 (squido 改反爬就崩)
- **法律灰色** — 可能违反 squido ToS

**实现风险**:
- Turnstile sitekey 检测到自动化 → 拒绝发 token → 整个流程阻塞
- mail.tm 临时邮箱被 squido 后期加入黑名单 → 注册全部失败
- Clerk 检测到批量同 IP 注册 → 全部账号封禁
