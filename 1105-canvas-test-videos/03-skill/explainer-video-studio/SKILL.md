# 解说视频工作室 · 一站式生产管线（v2.1，防回归架构版）

> **v2.2 修订（v8+二三集投产轮）**：新增六条通用原则——①**素材切片化**（大素材首次下载即切片，单片<20MB 目标几百KB~几MB，MANIFEST 标名用途，之后仅引用切片不重下）；②**一切叠层元素等比缩放**（浮水印 1231×1733 被非等比拉到 1080×1920=拉伸扭曲，修复=等比 fit 宽居中，新门禁 G14）；③**看不清的装饰不如不加**（顶部 8px 进度条用户"根本看不清"，v8 起移除；未明确要求的装饰默认不加）；④**镜间穿插应景视频防单调**（长纯 canvas 段偶插实拍/素材视频背景，优先"现有镜头视频背景化"零时间轴改动路线）；⑤**变速默认 1.0x**（提速仅用户明示；speed 段必须 -frames:v 帧数钳制防重采样漂移）；⑥**新集对齐工艺**（句级全局单调对齐 + jieba 分卡内建 v7 三铁律 + 透明页渲染器自动检测）。二三集配音实测比估算短 112~145s——再次证实铁律 12。
> **v2.1 修订（v7 审片轮）**：新增四铁律——①**管线分层：后处理常态化，字幕最后烧**（水印/裁切/变速/字幕/进度条/响度全部脚本段，在提速成片上烧字幕，字幕改动只重跑最后一步）；②**镜头边界语义归属**（概念分句必须完整落在"演它"的那镜内，画面语义不得比解说早一句）；③**字幕分卡最小信息量**（禁单字卡/纯标点卡）；④**同句同字号**（字号按句统一，禁逐卡分档）。新门禁：G11 语义锚点/G12 字幕质量/G13 端到端像素锚点。
> **v2.0 修订（规整轮）**：①铁律去项目化——项目专属数值移入"项目档案 Profile"机制，通用规则与项目参数分离，防止跨项目污染；②新增**防回归协议**（`references/anti-regression.md`）：单一事实源 + 开工对账 + 重写对账 + 感知维度门禁，来自实战中"已修复问题三度回归"的血泪复盘；③新增**文档优先协议**：外部平台操作先查路由表，探索是最后手段；④新增铁律：真实影片素材原生比例呈现。
> v1.x 版本史见文末。

本 skill 由五源整合：Remotion 渲染合规调研、Gemini 视频任务防踩坑指南（Token 黑洞与 H5 受控截帧架构）、娱资信息图 skill（品牌视觉系统）、三部曲解说片实操（网盘素材管线 + 分镜方法论 + timeline JSON）、v6 复盘轮（防回归架构）。

## §0 一句话用法（对用户的承诺）

用户只需提供：**风格 + 主题 + 时长 + 素材来源**（例："按小Lin说风格做一支10分钟竖屏解说视频，讲XX，文章和素材在我网盘，token是XXX"）。
本 skill 即输出：分镜表（求批准）→ 成片 mp4 + 字幕 srt + 分镜 timeline JSON + 全套中间件。

## §1 起点决策表（按用户给的东西定入口）

| 用户给了什么 | 从哪步开始 | 关键动作 |
|---|---|---|
| 只有主题（连文案都没有） | Step 0 选题+文案 | 按 `references/style-guide.md` 的改编 SOP/文风配方写口播稿（用户确认后才进分镜） |
| 有文章/报告（要改编） | Step 0.5 文案改编 | 同上，保骨肉去水分，口径以用户终稿为准 |
| 有口播终稿 | Step 1 事实核查 | `facts-gate.md` 门禁 |
| 有终稿+配音 | Step 3 对齐 | **配音实测对齐**：本地 faster-whisper（hf-mirror 拉模型）词级时间戳 + silencedetect 双校准（`scripts/align_final.py`），句首误差≤0.3s；字数权重只作分镜预览，**严禁直接投产** |
| 什么都有只要成片 | Step 4 起投产 | 按 timeline JSON 逐镜生产 |

**开工第一件事（不讨论例外）**：若项目有上一轮的工作仓，先跑 `assemble_* setup` 对账断言（或等价核对：字幕/分镜/时间轴与已验收交付物逐条对账），对平了才动第一根手指。详见 `references/anti-regression.md`。

素材来源决策：百度网盘（token→`scripts/netdisk.py`/`batch_download.py`，只读不上传）｜本地文件｜外部平台（**先查** `references/video-downloader-skill.md` §2 路由表）｜自制 canvas 动效（本 skill 主力）。

## §2 项目档案 Profile（通用规则与项目参数分离）

**所有版式数值（安全框坐标、字幕位、字号体系、配色、双版本策略）都不是 skill 的硬编码，而是项目档案参数。** 新项目开工时从用户反馈/参考视频中实测确定，写入项目 README 的 Profile 区；跨项目复用本 skill 时必须重新确认，禁止沿用上一项目的数值。

默认参考档案（来自实战项目验收，**仅作缺省示例**）：见 `references/layout-spec.md` §0——9:16 画布 + 4:3 横屏安全框（切上下黑边即得横屏版）+ 框外底部字幕条 + 品牌橙强调 + 阿里普惠体。

## §3 十步状态机（每步完成即落盘 `.step_N_done` 标记，幂等可续跑）

```
Step 0  选题与文案（若需）      → script.md（口播终稿，须用户批准）
Step 1  事实核查门禁            → facts_ledger.json（校验不过禁止进 Step 2）
Step 2  分镜表                  → storyboard.md + timeline.json（须用户批准）
Step 3  配音与对齐              → audio/S##.mp3 + 字幕权威卡 JSON（入库！见铁律 A6）
Step 4  素材拉取                → assets/（网盘/外部/截图，含 meta 留痕；外部平台先查路由表）
Step 5  canvas 动效制作         → canvas/S##.html（受控时钟 renderFrame API）
Step 6  受控截帧                → frames/S##/ + render-manifest.json（入场窗30fps∪2fps网格∪DENSE）
Step 7  组装混音                → build/（帧数精确架构 + setup 对账断言，见铁律 C 组）
Step 8  质检门禁                → BUILD_SUCCESS 或打回（技术健康 G1-G7 + 感知维度 G8-G10 + 锚点目检）
Step 9  交付                    → output/ 成片+srt+timeline+报告；决定正确性的中间件同步入库
```

工作目录结构（固定，长任务防崩）：`project/{script.md, facts_ledger.json, storyboard.md, timeline.json, 字幕权威卡.json, canvas/, frames/, build/, output/, worklog.md}`。**每完成一步 commit+push 到用户指定的 Git 工作仓（若有）；网盘源文件永不入 Git，只入切片/半成品/canvas HTML；"决定正确性的中间产物"（对齐字幕卡、分镜 JSON、关键脚本）与作品同级入库**。

## §4 硬性铁律（分六组，全部来自实测血泪，违反=返工）

### A. 工程纪律

1. **只有必须用 token 的才交给 AI**：可复用的一切（下载/截帧/对齐/组装/质检）必须脚本化；AI 只产出 JSON 配置与文案，不手写执行命令。
2. **ffmpeg 永远 `-nostdin -y`**；文字渲染 100% 走 HTML/CSS（或 PIL 降级），禁用 `drawtext`（沙盒常缺 freetype/中文字体）。
3. **token/cookie 永不落盘**：只走环境变量，不进任何产物/日志/Git。
4. **网盘只读**：素材只拉不上传；用户 Git 仓只放中间件与半成品（≤99MB/文件）。
5. **脚本即时入库**：写完就 commit，不许"用完再存"——沙盒回收不等人（实测：下载器脚本用完未入库，下一轮被迫重写）。
6. **中间产物分级入库**：作品（成片/srt）≠事实（对齐字幕卡/分镜JSON/时间轴）。**凡是用户验收过的东西，它的再生产依据必须同刻入库，并在文件头写清血缘（`_provenance`：生成方式/依据/验收状态）**。仓库里不许存在"名字合理但血统不明"的同类文件。

### B. 渲染与组装

7. **禁实时录屏**：Playwright `record_video_dir` 在沙盒高负载下掉帧导致音画错位；一律走受控时钟 `renderFrame(payload)` 截帧，静态区间单帧复用，只有动效窗口按 fps 截。
8. **帧数精确组装**：concat demuxer 对图像序列的 duration 会量化到 1/25s 网格（每镜 +0.01~0.02s，长片累积秒级漂移）。正确架构：每镜 `n_i=round(dur_i×fps)` 序列物化 → 逐镜编码 `-frames:v n_i` → `concat -c copy -video_track_timescale <fps×1000>`；分段终渲用 `-frames:v` 而非 `-t`；全片帧数必须 == round(总长×fps)。
9. **截帧覆盖全部动效时刻**：时刻集 = 开场窗 ∪ 自动入场窗（解析 data-t/data-counter）∪ 基础网格（承载环境微动）∪ 页面 `SHOOT_DENSE` 声明 ∪ 尾帧；页面动画超过网格采样密度时必须声明 DENSE。
10. **字体本地加载**：`@font-face` 用本地绝对路径，禁 Google Fonts/CDN；截帧前 `await document.fonts.ready`；ASS 烧录字体必须**系统注册**（ttf 复制 `~/.fonts` + `fc-cache`，`fontsdir` 不可靠），`Fontname` 写 `fc-scan` 精确 family 名，交付前抽帧目检字形。
11. **管线分层：后处理常态化，字幕最后烧（v2.1）**：
    - **canvas = 画面创意层**（动效/图表/背景视频）；**水印/裁切/变速/字幕/进度条/响度归一 = 后处理层**，全部由总装脚本的独立段完成，智能体只跑命令不碰中间产物——这些是与画布无关的常态化工作，逐个手工做=浪费 token。
    - **字幕烧录放最后一步**：在提速成片上烧（时间 = 权威卡 ÷k），而非烧进 1x 母带再提速。收益：字幕相关改动只重跑单次重编码的烧录段，不碰画面管线；提速重采样不再影响字幕。
    - 段序参考：帧序列→vtrack→final（只叠等比水印，无字幕无进度条）→audio→mux→speed（干净提速片）→**subs（最后烧字幕+出 srt）**→qc。
    - **变速默认 1.0x**（正常速度），提速仅在用户明示时；**speed 段必须 `-frames:v round(总长×fps)` 帧数钳制**——fps 重采样会漂 ±15 帧（实测 20207 vs 20192 致时长门禁边缘 FAIL），v4 就有此工艺、v7 丢失即回归，教训=移植老管线时逐段 diff 参数。

### C. 对齐与同步（音画不同步是观众最先感知的维度）

12. **配音实测对齐，禁字数权重投产**：字数权重×平均语速全片可漂移 ±20s 以上，观众在几十秒处即可感知。既有整条配音必须 whisper（本地 faster-whisper，HF 429 走 hf-mirror 手动下模型）+ silencedetect 双校准；字幕分卡用词锚定。估算值只用于分镜预览列。
13. **TTS 分句合成，严禁整篇**：跨句累积误差不可救；句内字幕按"汉字权重1.0+句末标点1.2"线性映射实测时长。
14. **字幕单一事实源**：每个项目只允许一个权威字幕卡 JSON（带 `_provenance` 血缘头）。组装脚本只许引用它；**开工时必须先与已验收的 srt 交付物逐卡对账**（卡数/文本/时间差阈值），对不上拒绝开工——这一步 30 秒，能省整轮重制。
15. **镜头边界语义归属（v2.1，画面比解说早一句=观众秒感知）**：
    - 分镜切镜时，**概念落点句（画面上的大字/盖章/结论元素对应的台词）必须完整落在"演它"的那一镜内**——推箱子镜头的台词必须说到"沉没成本"说完才能切盖印章。实测反例：边界切在词边界（某句说完最后一个字的瞬间），下一句（概念结论句）被分给不相关的新镜，画面语义早解说一句。
    - mid-sentence 切镜（B-roll 前景展示/证据切换）是合法剪辑，但仅限"解说继续、画面举例"的场景，概念落点句不得跨镜。
    - 断言（G11）：概念分句的 whisper 卡区间 ⊆ 镜区间；边界两侧无单卡严格跨骑（贴齐不算）。
16. **字幕分卡最小信息量（v2.1）**：whisper 词级分卡只按词边界，无信息量约束——实测全片 365 卡里 37 张是 ≤2 字卡（含 10 张纯标点卡「。」「，」闪现 0.3s）。规则：
    - 退化卡（去标点后有效字≤2）句内向后并入前卡（时间取首卡 start/末卡 end，零漂移）；
    - 句首纯标点/尾字→跨句向后并（上句的尾巴）；连接词句首短语（此外/而且/但…）→向前并入下卡；
    - 合并溢出（超单行容量）→按词界再平衡拆分，时间按有效字比例内插（漂移≤卡时长）。
    - 断言（G12）：全片无 ≤2 有效字卡。
17. **同句同字号（v2.1，"第一行小第二行突然变大"=观众秒感知）**：动态字号若逐卡独立分档，同句相邻卡档位不同即跳变（实测全片 246 处）。规则：**字号档位按感知单元（句/分句）统一=句内最长卡的档位**；跨句允许变档。档位写入字幕卡 JSON 的 `tier` 字段，ASS 生成只读 tier，不再自行计算。断言（G12）：同句相邻卡 tier 相等。
18. **成片提速不变调**：`setpts=PTS/k,fps` + `atempo=k` 一步完成；外挂 srt 全部时间戳 ÷k；QC 按新时长验收。提速后烧字幕时 ASS/srt 时间 = 权威卡时间 ÷k。

### D. 内容与设计

19. **事实门禁前置**：`facts_ledger.json` 每条数字带 claim/raw_inputs/formula/source_url/is_estimated，重算不过禁止开写分镜；推算值画面自动打"\*推算"角标；口径矛盾不静默改用户数字。
20. **节奏方差**：hook_punch / fast_list / deep_explain 三型交替，相邻两个 deep 之间必须插暴击或快闪。
21. **最小信息原则**：每镜只保留解释画面所需的最小必要信息，但不得精简到看不懂——像 PPT 演讲，只写讲话人实际说过的内容；口径类关键信息不可删。
22. **画面定格≤3s**：全部元素入场完毕后不得长于 3s 无变化；静态画面必须保持动感（typing/截图轮换/环境微动 float/pulse）；入场时刻按台词读音逐级浮现。连续动画（一直在动）是合法豁免。
23. **抽象镜头动画化（推理前置到分镜阶段）**：分镜表阶段就对抽象概念设计"用动画讲故事"的视觉隐喻（推箱子/下台阶/盖章/迷宫），连续运动全程 DENSE；不要做成静态文字卡后靠入场动效补救。方法论见 layout-spec §八。
24. **动效统一**：同一镜内一套入场原语；环境微动全片一套参数；镜间硬切是节奏语言，镜内不硬切。
25. **品牌实体必用官方 logo**；禁用间隔号 `·` 作美化分隔/替代换行（同句用逗号顿号，并列独立信息各自换行）；制作侧思考/口径括注不入画面正文。
26. **举一反三排查**：修一处问题时同类全片排查（grep/全镜扫描），但仅限确定同类，不动无关内容。
34. **看不清的装饰不如不加（v2.2）**：装饰性元素（顶部进度条/角标/花纹）若小到不可感知（实测：8px 进度条被用户评价"根本看不清"），加了=白烧一层编码+一个回归点。规则：**未明确要求的装饰默认不加**；已加的被反馈看不清则移除，且 QC 加反向门禁（如 G10 断言顶部无进度条）防旧链回归。
35. **镜间穿插应景视频防单调（v2.2）**：长片（>5 分钟）纯 canvas 段落易显单调，按"偶尔"密度（约每 2~3 分钟一处）穿插应景实拍/素材视频背景。**首选零时间轴改动路线**：把现有镜头 canvas 页透明叠层化（body/#bg-layer→transparent + scrim 0.6~0.8）+ bg 表挂切片，镜边界/Σ帧不动 → 音画同步零风险；素材可选不同时间窗/不同 take 避免画面重复。

### E. 素材

27. **外部素材失败预算**：每素材重试≤1 次、超时 5s 回退 canvas 自制动效或替代素材；静态图优先于视频。
28. **文档优先协议**：任何外部平台操作（下载/搜索/截图）前，**先查 `references/video-downloader-skill.md` 路由表并按表执行**；表中没有的通路才允许探索，探索预算=1 次换法，探索结论立即回写文档。禁止"凭印象先试一路撞墙再回头翻文档"。
29. **真实影片素材原生比例呈现（铁律，违者观众秒感知）**：
    - 影片作为**展示主体**（B-roll 前景/证据片段）：**fit 模式**——等比缩放进安全框舞台，完整可见，letterbox/pillarbox 用底色 pad，禁止裁切放大；
    - 影片作为**氛围底**（scrim 压暗做背景纹理）：可 cover 舞台框（等比放大后裁切，无拉伸），竖版源全宽可见；
    - **任何模式都禁止非等比拉伸**；QC 必须做几何断言（抽帧实测窗口矩形 == ffprobe 源分辨率推算值）。
    - 记住：`force_original_aspect_ratio=increase` + crop 对 16:9 源铺满 9:16 = 横向只可见 ~32%——这不是"风格"，是事故。
36. **素材切片化（v2.2，沙盒崩溃恢复的成本杀手）**：大素材（视频原片/长音频/教程库）**只在第一次下载时碰原件**，下载完成立刻按分镜需求切成小片段入库，之后任何会话只引用切片：
    - 单片硬上限 **20MB**（Git 友好），目标**几百 KB~几 MB**（长源可预缩到目标宽，如 2880×1800 延时→1080 宽）；
    - 切片清单 `clips/MANIFEST.json` 每片标好**来源/时间窗/用途/被哪些镜头引用**（"标好素材的名字和用途备用"）；
    - 切片只做**等比缩放**（`force_divisible_by=2` 防奇数高炸 x264）；音频配音/BGM 每个 ≤20MB 可整文件入库；
    - 幂等切片机 `scripts/slice_materials.py`；实测教训：323MB 延时每次崩溃恢复重下 90s+烧 token，切片化后 1.5~6MB/片随仓带走。
37. **叠层元素等比（v2.2，浮水印拉伸扭曲教训）**：水印/角标/贴纸等 PNG 叠层**绝不非等比缩放铺满画布**——品牌浮水印 1231×1733（比例 0.710）被拉到 1080×1920（0.5625），横向压 0.88×/纵向拉 1.11×，用户一眼看出"拉伸扭曲"。正确做法=等比 fit 一边、另一边居中留透明带；门禁 G14 断言成品水印内容宽高比与原版一致（±2%）。

### F. 质检与交付

30. **机器门禁两级**：技术健康（G1-G7：零坏帧/帧数/时长/分辨率/响度/无长黑屏/无渲染器元数据）+ **感知维度（G8-G13：字幕对账/素材几何/UI连续性/语义锚点/字幕质量/端到端像素锚点）**，模板见 `references/anti-regression.md` §4。全部 PASS 才 BUILD_SUCCESS。
31. **目检锚点化**：VLM/人眼抽帧检查必须"先算期望再对照实读"（字幕锚点/几何锚点），不做自由描述——感知级检查会误报（实测：把源片贴地特写误判为拉伸变形），几何争议一律像素 diff 仲裁。
32. **渲染水印合规**：若用 Remotion 渲染，交付前清容器元数据。
33. **双版本交付**（若项目档案要求横屏版）：crop 切框前后顺序要明确（水印先叠后切、进度条切后重画、字幕各自独立烧），双版本 QC 全过才交付。

## §9 防回归协议与文档优先协议（v2.0 核心，必读）

详见 `references/anti-regression.md`。三句话版本：

1. **修复的完成标志不是"这次对了"，而是"下次想错都错不了"**——每个 bug 修复必须落成机器断言（setup 对账 / QC 门禁）。
2. **单一事实源 + 开工对账**——权威数据只有一个文件、带血缘头；新会话开工先对账旧世界的账。
3. **查表优先，探索殿后**——外部操作先路由表，worklog 引用所循文档行；无文档才探索，探索结果回写文档。
