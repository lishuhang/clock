# 防回归协议（references/anti-regression.md）

> v2.0 新增。来源：实战项目中"音画同步、素材比例、进度条"三处**已修复问题在后续版本全部回归**的血泪复盘（完整复盘见项目工作仓 `05-retro/RETRO.md`）。
> 一句话：**修复成果若只存在于"会话记忆/沙盒文件"里，就等于没有修复。必须让它们存在于"仓库 + 机器断言"里。**

## 1. 为什么会回归（病理，每个新会话都要警惕）

| 病理 | 机制 | 实例 |
|---|---|---|
| 修复未入库 | 沙盒回收后，修复用的中间产物/脚本消失，新会话拿到仓库里的**旧文件**当权威 | whisper 字幕卡 JSON 未 commit，v5 会话烧了仓库里的 v2 旧对齐文件，字幕漂移 ±27s 复发 |
| 重写丢修复 | 重写管线代码时，旧实现里"为什么这么写"的注释/逻辑不被理解，被当冗余删掉 | 分段进度条的段偏移 `t-t0` 在重写时消失，进度条中点重置、永远不满格 |
| 规格沿用过期 | 素材的角色变了（氛围底→展示主体），规格层的处理规则没跟着改 | "背景层拉伸铺满"规则用于真实影片 → 16:9 原片放大 3.2× 只露中段 |
| 门禁盲区 | QC 只测"技术健康"（文件合格），不测"用户感知"（字幕对不对位/比例正不正常） | 字幕烧错时间轴，七道门禁全绿灯放行 |
| 长上下文稀释 | 规则写在几万 token 之前，"记得大概"的幻觉压过"精确遵循" | 铁律写着"禁字数权重投产"，烧字幕时没人核对当前文件是不是字数权重产物 |
| 探索优先 | 接到子任务直接凭印象开干，文档路由表被考古层化 | B站下载先撞 API 412 和第三方站，才回头查文档里的免登录通路 |
| 感知误报 | VLM/人眼对特殊构图会误判"变形"，对真变形也可能放过 | 源片贴地特写（脚在上、地面占满）被 VLM 判为"裁切拉伸"，像素 diff 证明完全正确 |

## 2. 单一事实源制度

每个"决定正确性"的数据类型，项目内只允许一个权威文件：

| 数据类型 | 唯一事实源 | 禁止 |
|---|---|---|
| 字幕卡（文本+时间） | `字幕权威卡.json`（带 `_provenance` 头） | 散落的旧对齐 JSON、无名分卡文件 |
| 分镜/时间轴 | `timeline.json`（用户批准版） | 各版本 shots JSON 并存且不标新旧 |
| 对齐基准 | 已验收交付的 srt（对账真值） | 用估算产物充当真值 |

权威文件格式约定（JSON 头部）：

```json
"_provenance": {
  "what": "本文件是什么（唯一事实源声明）",
  "alignment": "生成方法（如 whisper 词级 + silencedetect 双校准）",
  "source": "从哪个已验收交付物派生/对账",
  "history": ["各版本沿革，作废的注明'作废，仅存档'"],
  "checks": "开工对账的断言内容"
}
```

**入库纪律**：权威文件与成片同级 commit；仓库里不许出现"名字合理但血统不明"的同类文件——发现旧文件立即在 `_provenance.history` 标注作废或删除。

## 3. 开工对账断言（每轮会话第一件事）

组装脚本设 `setup` 段，开工前强制对账，任何一项不符直接退出：

```python
# 字幕对账（G8 前置）
cards = load_subs()                      # 唯一事实源
gt = parse_srt_cards(GROUND_TRUTH_SRT)   # 已验收 srt
assert len(cards) == len(gt) == EXPECT_N
for a, b in zip(cards, gt):
    assert a["text"] == b["text"]
    assert abs(a["start"]-b["start"]) <= 0.011 and abs(a["end"]-b["end"]) <= 0.011
```

对账对象的选择：**用户验收过的交付物**（srt/成片抽帧实测值）> 权威 JSON > 其他一切。30 秒的对账，挡住整轮重制。

## 4. 感知维度门禁（G8-G13 模板）

技术门禁（G1-G7：坏帧/帧数/时长/分辨率/响度/黑屏/元数据）只证明"文件合格"。以下六道门禁证明"用户会点头"：

**G8 字幕同步对账**：烧录 ASS 卡数与权威源一致（分层架构下单次烧录，两版本卡数 == JSON 卡数）；（有条件时）抽锚点帧读字幕与权威卡比对。

**G9 素材几何断言**：每个嵌入视频镜抽帧，实测窗口矩形 vs ffprobe 源分辨率推算期望（等比缩放进舞台框的取整规则与 ffmpeg 一致），容差 ±6px：

```python
def expected_fit_rect(src_w, src_h, box_w, box_h):
    scale = min(box_w/src_w, box_h/src_h)
    w, h = int(round(src_w*scale))//2*2, int(round(src_h*scale))//2*2
    return ((box_w-w)//2, (box_h-h)//2, w, h)   # 舞台框内居中
# 实测：窗口行/列与 pad 底色差异 > 阈值即视频内容；行列范围即窗口矩形
```

**G10 UI 连续性断言**：进度条等随时间单调演进的 UI 元素，在分段边界前后 + 片尾抽帧测量（如顶部橙色像素宽度），断言：单调不重置 + 终值到位。分段渲染的任何"随全局时间变化的元素"（进度条/倒计时/背景音乐卡点）都必须过这道门禁——**分段偏移丢失是重写管线时最常见的回归**。

**G11 语义锚点（v2.1，治"画面比解说早一句"）**：每个"概念落点句"（画面上的大字/盖章/结论元素对应的台词）的 whisper 卡区间，必须完整落在"演它"的那一镜内：

```python
# 锚点表：[(镜ID, 分句特征子串), ...]
# 卡区间 = key 在全文卡流中覆盖的最小卡区间 [首卡.start, 末卡.end]
assert span.start >= shot.start and span.end <= shot.end
# 附加信息级：边界处无单卡严格跨骑（start<t 且 end>t；贴齐边界不算）
```

注意：mid-sentence 切镜（B-roll）合法，不能用"句不跨镜"做全局硬断言；硬断言的是概念分句归属。

**G12 字幕显示质量（v2.1，治单字卡与同句字号跳变）**：

```python
# 无退化卡：全片无"去标点后有效字≤2"的卡（合并规则见 SKILL.md C16）
# 同句同档：同句相邻卡 tier 相等（档位=句内最长卡定档，见 SKILL.md C17）
# 单行宽度：每卡 vlen(text) × 字号 ≤ 可用宽度（含 ASCII 0.55 折算）
```

**G13 端到端像素锚点（v2.1）**：在成片指定时刻抽帧，断言语义画面元素在场（如"沉没成本"大字落地时刻的舞台带红像素量、「同质化」盖章时刻的印章红像素量）——把"语义对位"从图纸断言延伸到成片像素。另：字幕在场验证用"干净片 vs 字幕片同帧 diff"，差异必须精确落在字幕带（带外污染≈0）。

## 5. 重写对账纪律

重写任何管线段之前，先列出旧实现的**已验证行为清单**（读旧代码 + 查 worklog 踩坑记录），逐条核对新实现保留：

1. 旧代码里每个"看起来奇怪"的行（偏移量/取整/特殊参数）都是某次踩坑的化石，先考古再决定去留；
2. 清单核对完才允许删旧代码；
3. 重写后跑全部门禁（含 G8-G13），不允许"只验新功能"。
4. 优先**最小 diff 改造**（复制旧版 → 外科手术式修改）而非凭理解重写——v7 即在 v6 全量复制上改 7 处，v6 已验证行为零丢失。

## 6. 锚点式目检（VLM/人眼的正确用法）

- **禁止**自由描述式目检（"看看画面有没有问题"）——误报漏报都多；
- **必须**先算期望再对照：字幕锚点（t 时刻应显示的字卡文本）、几何锚点（窗口应为的矩形）、状态锚点（进度条应为的宽度）；
- 几何争议一律**像素 diff 仲裁**：手工按同参数链生成参考帧，与产物做逐像素差（编码噪声量级 <10 为一致），不信目测；
- 每个项目维护一个锚点表（v3 修复验证点、片尾卡、最深漂移处……），QC 抽帧按表执行。

## 7. 入库清单模板（每轮交付前自查）

```
[ ] 成片 + srt + qc 报告                       （作品）
[ ] 权威字幕卡 JSON（带 _provenance）           （事实）
[ ] timeline/shots JSON（用户批准版）           （事实）
[ ] 全部管线脚本（含当轮新写的工具脚本）         （再生产能力）
[ ] production-report（含已知妥协清单）          （决策记录）
[ ] worklog verbatim 条目                        （过程证据）
```

## 8. 给下一个会话的三句话

1. 凡是老板验收过的东西，它的"再生产依据"必须同刻入库并写清血统——作品入库不算备份，事实入库才算。
2. 修复一个 bug 的完成标志不是"这次对了"，而是"下次想错都错不了"——没有断言的修复等于没修。
3. 长会话不可信，开局先对账——先跑 setup 断言把旧世界的账对平，再动第一根手指。


## §7 v2.2 增补（v8 + 二三集投产轮实战沉淀）

### 新门禁
- **G10 反转（无进度条）**：装饰移除后必须加反向断言（顶部 8 行无品牌橙 < 50px），防旧滤镜链回归。
- **G14 叠层等比**：成品水印内容 bbox 宽高比 == 原版素材（±2%）；资产级检查 + 管线 overlay 链无缩放（overlay=0:0 双方同尺寸）双保险。
- **G9 多帧采样**：cover 模式几何检查采 3 个时刻取最大行数——暗场/夜景内容会令单帧采样误报"不满格"（实测 T2 木偶戏 442/810 行实为暗画面，几何正确）。fit 模式同理适用。
- **G13 字幕带抽样**：成片 3 个卡中点抽帧，字幕带（Y1435~1545）白像素 > 800——验证字幕真实烧入且时间正确，成本低。

### 新坑实录（重蹈或新发，全部已修）
1. **speed 段丢 `-frames:v` 帧数钳制**：v4 有此工艺，v7 重写时丢失 → fps 重采样漂 +15 帧致时长门禁 0.52s FAIL。教训：**移植/重写管线时逐段 diff 参数**，"架构复用"不等于"参数复用"。
2. **部分残骸文件骗过 getsize>1MB 幂等检查**：超时被杀的 final_h_A.mp4 有 7.6MB 但 0 帧，`os.path.getsize` 检查放行 → concat 失败。教训：**幂等检查用帧数（probe_frames）不用文件大小**。
3. **cp 重置丢已应用的补丁**：`cp v7 v8` 后再跑补丁脚本，第一批常量区编辑被覆盖。教训：**改造流水线：完整补丁脚本一次跑完 → 语法断言 → 特征断言（残留引用 grep），中途不重置基线**。
4. **逐句独立对齐产生乱序/负窗**：每句单独 SequenceMatcher 匹配整条字符流，短句（"大家好欢迎回到"）会命中错误位置。教训：**全局一次对齐（整个脚本流↔whisper 流）+ 句边界按累计偏移映射时间**，单调性由构造保证。
5. **jieba 分卡标点宽度**：打包预算若按去标点字数（eff_len），"截然不同，适合的平台也各有侧重。"类卡片实宽 16 > 容量 15。教训：**分卡预算用 vlen（含标点视觉宽度）**，退化合并前先做尾部再平衡（末两卡合并从中点重切）。
6. **后台下载进程被会话回收**：setsid/nohup 均不可靠（v7 已知，v8 再证）。教训：**前台 timeout 分段跑 + 幂等断点续传**（para_dl 段合并、curl -C -）。
7. **单字高奇数炸 x264**：2880×1800 等比缩到 1080×675（675 奇数）→ "Could not open encoder"。教训：切片/缩放一律 `force_divisible_by=2`。
8. **PIL paste 破坏 RGBA**：paste(im, pos, im) 自身做 mask 会把 alpha 搞成 max=1（水印全毁）。教训：**全尺寸透明层直接 paste（无 mask）→ Image.alpha_composite**。
