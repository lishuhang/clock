# 0724-tts TTS Voice Lab v2.19 修复交接

## 完成情况

### 根因定位
- 问题现象：NiceVoice 克隆上传 R2 成功(200)，saveRefAudio2 返回 200，但 TTS 始终返回 400
- 根因：Worker 代码将所有 /api/nv/* 请求都走 HMAC 签名代理（nvProxy），但上游 /clone/tts 端点拒绝签名请求，返回 400
- 验证方式：通过浏览器自动化抓包 turbovoice.online 官网，发现官网 TTS 请求不携带任何 HMAC 签名头
- 附带发现：
  - 上游已从 COS 迁移至 R2 存储，getSyncRefStatus 轮询中的 “Reference files not found in COS” 是瞬态错误，约 20 秒后自动恢复
  - 任务状态查询端点为 getItemByTaskSn（非 getTaskStatus，后者已 404）

### 签名需求矩阵（实测）

| 端点 | 签名 | 无签名 |
|------|------|--------|
| /clone/getUploadUrl | 200 OK | 200 OK |
| /clone/saveRefAudio2 | 200 OK | 500 ERR |
| /clone/getSyncRefStatus | 200 OK | 200 OK |
| /clone/tts | **400 ERR** | **200 OK** |
| /clone/getItemByTaskSn | 200 OK | 200 OK |

### 修复内容（v2.19）
- Worker 服务端：/clone/tts 和 /clone/getItemByTaskSn 两个端点走不签名代理，其余端点保持签名
- 版本号升至 2.19.0，changelog 已更新
- 代码已通过 node -c 语法检查
- 端到端验证通过：克隆(签名) -> TTS(不签名) -> getItemByTaskSn(不签名) -> 下载 MP3 成功

## 技术备注

### NiceVoice API 当前状态
- 存储已迁移至 R2（r2.cloudflarestorage.com）
- HMAC 签名机制仅用于克隆管理端点（saveRefAudio2 必须签名）
- TTS 端点完全不需要签名（官网也是不签名的）
- getUploadUrl 返回的 storageType 字段无实际控制作用，无论传 cos 还是 r2 都返回 R2 URL
- 克隆训练同步有 20 秒左右延迟，期间 getSyncRefStatus 返回 error=1，属正常行为
