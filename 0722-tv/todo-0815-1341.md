## 5. 关键技术事实与避坑清单

| 主题 | 必须遵守的事实 / 策略 |
|---|---|
| 用户发布清单的 345 URL | 必须使用用户自定义域名形式，不能用 `workers.dev` 形式作为面向中国大陆用户的清单地址。 |
| 345 playlist 与 segment | playlist 与 segment 均须禁用缓存；为避免 segment 过期，应缓存 session URL（历史实现为约 60 秒）并通过同 session 实时转发。 |
| 345 源请求头 | 动态源通常要求移动端 User-Agent 与正确 Referer；不要简化为无头直连。 |
| Workers 外网限制 | Workers 不能可靠抓取裸 HTTP IP；来源重定向至 HTTP IP 的线路应作为不能通过 Worker 中转处理，而非盲目重试。 |
| WSO 错误恢复 | 动态 m3u8 返回 403 时应在同一请求中清空缓存、重新解析 API、取得新 URL 后重试；跨请求重试会造成 API 缓存死循环。 |
| YSP 可播放性 | 需单独检验 HTTP、playlist、segment 与浏览器解码链路；绿屏应被分类为“可取流但浏览器不可解码”，不是“完全可用”。 |
| 检查语法 | 任何修改的 Worker 都要先用 `node --check <file>`；`application/javascript` 是此前可用的部署内容类型。 |
| blind 版本 | 不能包含频道中文名、目录 UI、README 或 changelog；仅返回必要状态 / m3u8 代理结果。 |
| GitHub 自动覆盖风险 | 历史上另一个自动刷新仓库会定期重新部署 `iptv345`。现网 Worker 修改后，必须确认是否仍有外部构建/部署者；否则下次自动执行可能覆盖本轮改动。 |
