# 140字摘要 v1.10 — 调试工作日志

- 日期：2026-10-03（Asia/Shanghai）
- 产物：`chrome-140word-v1.10.zip`
- 任务：修复「复制全部」在另一浏览器上不遵循设置中摘要格式的问题

## 一、问题现象

- 浏览器 a（Edge，v1.9）：设置 `summaryFormat = format2` 后，「复制全部」输出 `标题 / 摘要：… / 链接 / ---`，格式正确。
- 浏览器 b（Edge）：手动修改设置、或导入浏览器 a 导出的设置 JSON，「复制全部」仍输出旧格式——以 `140字摘要 - 历史记录导出` 开头，含 `导出时间 / 共 N 条记录 / 【时间戳】/ 标题: / 链接: / 模型: / 摘要:` 等元数据字段。

## 二、根因分析

1. 对 v1.9 源码全文检索：`历史记录导出`、`导出时间`、`模型:` 等特征字符串**均不存在**。v1.9 的 `exportHistory()`（background.js）只会输出三种统一格式（format1/2/3）之一，绝不输出带模型/时间元数据的格式。
2. 因此浏览器 b 的「复制全部」文本只能来自**旧版 background.js 的 exportHistory 代码路径**（v1.9 之前版本的导出格式）。
3. 旧版后台的导出逻辑不读取 `summaryFormat` 设置——这解释了为什么「手动改设置」与「导入设置」都无法改变其输出：设置写入成功了，但旧代码根本不消费该设置。
4. 成因判断（两种情形之一）：
   - 浏览器 b 安装的插件本身就是旧版本；
   - 或插件已更新，但旧的后台 Service Worker 实例未被替换（界面已是新版、能改格式设置，后台仍运行旧代码——Chromium/Edge 在扩展更新后未完全重启浏览器时可能出现）。

> 结论：这不是 v1.9 设置读写逻辑的缺陷，而是「浏览器 b 上后台脚本版本错位」的问题，且此前插件没有任何机制能让用户察觉这种错位。

## 五、浏览器 b 的修复步骤（用户侧操作）

1. `edge://extensions` 中移除旧版本插件（若与当前版本并存）；
2. 安装/加载 `chrome-140word-v1.10.zip`（解压后「加载解压缩的文件夹」，或拖入 zip 安装）；
3. **完全退出并重启浏览器**（确保旧后台 Service Worker 终止）；
4. 重新打开侧边栏：正常情况下无警告条、footer 显示 v1.10；若摘要页顶部出现橙色「后台脚本版本不一致」警告条，说明旧后台仍在运行，重复步骤 3；
5. 通过「设置导入/导出」恢复浏览器 a 的设置后，「复制全部」即按 format2 输出。
