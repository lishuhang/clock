> **用户请求（概括）：** 查看 `lishuhang.me` 前两篇同步博客文章为什么图片裂开；若为脚本问题则修复并刷新版本号。

3. 发现同一目录存在转换后的 JPG，但文章仍引用转换前 PNG。例如：
   - 8 月文章的 `01.png`、`04.png`、`12.png`、`13.png` 不存在，实际为相同文件名的 JPG；
   - 7 月文章的 `01.png`、`02.png`、`04.png` 不存在，实际为 JPG。
4. 同目录未转换的 PNG（如 8 月文章的 `02.png`、`03.png`）可正常加载，因此排除图床整体故障、Jekyll 路径改写故障与 weserv 整体不可用。

> **根因结论：** 这是 **blog 上传脚本的格式转换后 URL 回写缺陷**，不是图床仓库、站点配置、Jekyll 插件或 weserv 故障。

## 五、建议的后续检查清单

下一代理接手时，建议先完成以下检查，而不是立即修改代码。

1. 在 Windows 生产目录确认 `.env` 仍存在，并检查 `logs/task_completion.json`、`tmp/` 与根目录待领取摘要没有被异常清空。
2. 明确询问用户是否需要恢复 `keepitrun.py`；**不得自行重启**，因为当前停止是经过用户明确授权的部署后状态。
3. 若恢复后 blog 在当天触发，重点查看 `logs/blog_*.log` 是否出现“格式转换”和“已回写 N 个转换后图片 URL”的日志。
4. 若仍有断图，依次检查：文章 Markdown 引用、图床实际 Contents 文件清单、站点 `image_prefixes` 日期规则、公开 raw URL、weserv 响应；不要直接假设是图床故障。
5. 若 Photos 新增月份图片，先确认 photos `_config.yml` 对该月有唯一匹配规则，再运行 `05_photos-update.py`；不要让脚本静默回退到旧仓库。
6. 若 GLM 再出现新的拒答格式，添加最小化的测试用例并扩展拒答识别；必须保持“最终英文原文保底”不变。
7. 每轮修改结束后创建新的增量 `todo-MMDD-HHMM.md`，在发布前完成脱敏检查与归档。

## 六、故障排查经验与避免重复踩坑

| 问题 | 真实原因 | 正确处理 | 不应采取的做法 |
|---|---|---|---|
| 主站局部图片裂开 | 图片压缩转换后，Markdown 没有更新扩展名。 | 对照文章路径与图床实际文件；修复脚本回写并最小化修旧文章。 | 盲目改站点前缀、重建全部图床、重复上传同名文件。 |
| 私有 img2 无法展示 | 浏览器/weserv 不带 GitHub 凭据读取 private raw URL。 | 改为公开仓库或配置公开 CDN/代理。 | 在公开网页中嵌入凭据或假定 raw 私有地址可用。 |
| 生产部署被阻断 | keepitrun 正在运行。 | 默认停止部署并询问用户；获授权后只停止目标进程。 | 擅自停止进程或部署到运行中的脚本目录。 |
| PowerShell/远程命令引号异常 | 多层 shell 对变量和引号有转义问题。 | 用独立 ASCII 脚本、校验和、或编码命令；每步验证。 | 反复执行同一条失败命令，或跳过备份验证。 |
| GitHub Contents API 归档 ZIP 失败 | 大文件请求可能出现 JSON 解析异常。 | 使用 Git 数据 API：创建 blob、tree、commit，再更新 ref。 | 为绕过失败而将 ZIP 拆分到非归档路径或使用未校验第三方上传。 |
| GLM 输出拒答错误文本 | 模型安全拦截或单条拒答。 | 识别拒答、尝试下一个引擎、最终保留英文源内容。 | 把 API 错误写进摘要，或丢弃原始新闻条目。 |
