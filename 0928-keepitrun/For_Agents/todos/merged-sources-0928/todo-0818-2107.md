### 积压摘要和去重的当前语义

1. 根目录中的 `YYYYMMDD-HHMMSS.md` 是用户尚未取走的 RSS 摘要；历史错误后缀 `YYYYMMDD-HHMMSS.py` 同样视为待处理摘要。
2. 合并器会自动发现全部待处理摘要，并将它们与传入的新 RSS 文件一起解析、链接规范化和去重。即使不传任何新 RSS 参数，也可以单独收敛积压摘要。
3. 同一最终 URL 的多条记录只保留描述最长的一条。链接规范化会移除片段、追踪和探测参数，但保留用于定位文章的参数。
4. 新摘要成功原子写入后才删除旧摘要。因此目录最终只保留一个新的 `.md`，覆盖用户上次取走之后到当前的全部不重复条目。
5. 主调度器在仅发现积压摘要而没有当天 RSS 时，优先运行合并，不额外抓取 RSS；如果存在当天 RSS，则两者一起合并。

### 翻译保底的当前语义

- 正常顺序仍是 Gemini → GLM HTTP API → Google Free Translate。
- GLM 对特定内容返回常见拒绝性文字、空文本或不可用结果时，条目保留原始英语标题；不得写入拒绝提示、空行或丢失链接。
- 所有翻译引擎均失败时，也必须生成摘要并保留原文。产物可靠性优先于语言转换完整性。

| 首次启动重复抓取 RSS | 改为按 GMT+8 时段和中间文件数量恢复。 | 不要为了凑两份 RSS 而重复抓取。 |
| 任务命名混乱 | 采用 01–05、90–92 的统一命名。 | 不要无边界批量替换已编号名称；检查常量、首次启动、主循环、日志和 README。 |
| 合并器强制要求输入文件 | 改为允许零个新 RSS 输入，仅收敛积压。 | 任何 CLI 参数变更都须覆盖恢复路径。 |
| GLM 单条拒绝 | 回显英语原文。 | 翻译失败时不得丢失链接或标题。 |
| 脱敏扫描误报代码变量 | 调整扫描逻辑，禁止 `.env` 入包并检查真实密钥格式及模板配置。 | 不得为消除误报而降低对实际凭据的防护。 |
| 生产端批量散列命令无响应 | 中止命令，未重复覆盖生产文件。 | 生产验证使用短、单一命令；失败时先诊断再重试。 |
| 博客脚本文档转义警告 | 发现历史警告但未混入 v1.19 修改。 | 若处理，必须在独立的博客抓取回归任务中进行。 |

## 当前未完成项与后续建议

本轮 v1.17–v1.19 的用户需求均已完成。没有已知的功能性待办项。以下不是未完成需求，而是安全维护建议：

1. 若需要验证真实定时运行，请先征得用户同意，并避免在任意时段直接启动主程序触发首次启动任务；应选择可控时段或使用隔离夹具验证。
