## 3. YSP 浏览器播放绿屏问题 (encrypt:2)

### 现状
- ysp TS 段使用 `encrypt:2` 加密 — H.264 NAL 单元被部分加扰
- 标准 hls.js 无法解密
- 浏览器播放报 `bufferAddCodecError` 或显示绿屏
- VLC / MPV / ffprobe 等原生 TS 播放器可正常播放 (不经过 MSE)

### 限制
- ysp 自有解密: `hls.cmg.js` + `keygen_bg.wasm`
- 需要逆向 ysp 的自定义 hls.js fork

### 方案: 集成 ysp 自定义播放器 (大工程)

**步骤**:
1. 抓取 ysp 的 `hls.cmg.js` 和 `keygen_bg.wasm`
2. 在 tv-app-v1.x.html 中加载这些文件
3. 替换标准 hls.js 为 ysp 的 hls.cmg.js
4. 测试是否能解密播放

**风险**:
- ysp 可能定期更新混淆算法
- hls.cmg.js 可能依赖 ysp 页面环境 (cookies, tokens)
- 维护成本高

**建议**:
- 不在 v2.8 解决
- 用户优先使用 VLC / PotPlayer / IINA 等原生播放器播放 ysp 源
- 浏览器播放使用 345 源 (港澳台/央视/卫视) 代替

| itv40 | 东方卫视 (itv 源) | 302 → ?tid=ws | 源站已删除该 ID |

### 限制
- 这是源站本身的问题，CF Worker 无法修复
- 这些频道在源站分类页仍可见，但点击播放时 m3u8 服务器返回 404 / 302

### v2.8 已实现的缓解措施
1. **broken channel cache**: 检测到 404/302 后，将频道加入 broken cache (10 分钟 TTL)，避免持续请求源站
2. **更清晰的错误消息**:
   - `channel not available at source (redirected to ?tid=gt)` — gt15 / itv40 类
   - `channel moved at source (still redirecting after 5 hops)` — migu41 / migu83 类
   - `stream broken at source (404 at m3u8 server)` — gt16 / gt18 / gt20 / ys2 / ws4 类
3. **/refresh/<tid><id> 端点**: 用户可手动强制刷新某频道，绕过 broken cache

### 建议
- 在 tv_list-v2.txt 中**移除**这些失效频道
- 或保留但标记为备用 (用户在前端可隐藏)
- 定期重新测试源站，若恢复则自动恢复 (broken cache 10 分钟过期)

## 5. 港澳台频道音调越来越低沉问题

### 现状
- 用户反馈: 翡翠台、无线新闻等播放一段时间后声音越来越低沉、音画不同步
- 这是 hls.js 的 backBuffer 累积问题，不是 Worker 的问题

### v2.8 缓解措施
1. 在 m3u8 响应中注入 `#EXT-X-PROGRAM-DATE-TIME` — 帮助 hls.js 更准确地定位 live edge
2. CDN 缓存控制 (已有): `CDN-Cache-Control: no-store` 确保 m3u8 每次都拿到最新

### 待 tv-app-v1.3 实现的修复
- 设置 `backBufferLength: 10` (秒) — 丢弃 10 秒前的 back buffer
- 设置 `liveSyncDurationCount: 3` — 跟随 live edge 3 段
- 关闭 `lowLatencyMode` (源站不是 LL-HLS)
- 长时间缓冲检测 (60 秒) → 刷新同一个源 / 换源

### 详见
- `tv-app-v1.3.html` 的 hls.js config 修改
- `iptv345-dev-history-0722.md` 第 4.6 节
