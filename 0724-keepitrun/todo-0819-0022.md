用户要求把主站已有的“按 `_config.yml` 日期范围选择图片前缀与图床仓库”的能力复刻至 daily 与 photos，并将 keepitrun 升级到 v1.21。具体要求包括：核验主站能力；daily 与 photos 按配置切换图床；blog、daily、photos 三个上传/同步子脚本在传图或扫描前读取目标站 `_config.yml` 决定仓库；photos 在 2026-07-31 及此前使用 `modem-56k/img`，自 2026-08-01 起使用 `modem-56k/img2`；图片相对路径保持 `YYYY/MM/DD/文件名`；用户随后运行 keepitrun 时，blog/daily 不应产生无效更新，photos 应检测并同步 8 月图片；交付更新后的三个站点配置/程序、v1.21 生产部署与脱敏归档。用户要求在设置 photos 图床前无人值守操作，并强调最小权限、不得写入凭据、发行包只能包含 `.env.example`。

用户后来明确授权将 `modem-56k/img2` 改为公开，以满足公开 photos 页面加载 8 月图片的要求。

## 已完成的 v1.21 实现

### 1. 图床路由模块与 keepitrun

在 keepitrun 发行副本新增 `image_routing.py`。它不依赖 PyYAML，解析当前项目使用的受限 `image_prefixes` YAML 结构，并校验日期格式、范围重叠、仓库格式、分支、路径前缀与缺失配置。上传路由由 `prefix`（展示 URL）与 `upload.repository`、`upload.branch`、`upload.path_prefix`（写入/扫描目标）组成。

`03_convert-daily.py` 会在带图发布前读取 `lishuhang/daily@main` 的 `_config.yml`；`04_convert-blog.py` 会在带图发布前读取 `lishuhang/lishuhang.github.io@main` 的 `_config.yml`。二者按文章日期选择仓库与分支，无法确定路由时停止本次带图发布，防止静默写入旧仓库或留下失效图片引用。文章 Markdown 仍发布到原博客仓库。

`05_photos-update.py` 不再固定扫描一个图片仓库。它在每个待同步月份前读取 `lishuhang/photos@main` 的 `_config.yml`，按路由扫描对应的图片仓库与分支，并将该月公开 `base_url`、来源仓库和分支写入 `data/YYYYMM.json`。自动模式会从最新 JSON 月份（含）检查至当前月份；只有 JSON 内容差异才会提交。

主调度器 `keepitrun.py` 已更新为 `VERSION = "1.21"`、`VERSION_DATE = "2026-08-19"`，并将 `daily`、`blog`、`photos_update` 纳入 v1.21 的版本感知任务映射。README 已更新为 v1.21 并记录配置规则、路径规范、排障和变更日志。

### 3. img2 可访问性

初始核验发现 `modem-56k/img2` 为私有仓库，未认证的实际 8 月图片 raw URL 返回 404，因此公开 photos 页面无法展示。经用户明确授权，已将其改为公开仓库，默认分支仍为 `main`。之后对实际文件 `2026/08/01/20260801 081637.jpg` 的公开 raw URL 核验为 HTTP 200，`image/jpeg`。因此 photos 的 2026-08 raw 前缀已可公开使用。

### 4. 主站可用性核验

以已发布文章 `2026-08-12-wo-men-jiu-shi-hui-bu` 验证：仓库源文使用 `/2026/08/12/...` 相对图片路径，线上页面实际输出 `https://lishuhang.me/img/2026/08/12/...`，封面使用 weserv 代理。因此主站当前生产页面的图床前缀改写可用。本轮未改变主站实际图片展示前缀。

## 重点踩坑与后续注意事项

1. 原有主站和 daily 的日期规则写成 `[null, "2026-07")` 与 `["2026-08", null)`，按半开区间语义会遗漏整个 2026-07。因为两段实际前缀及上传目标相同，已安全修正为第一个范围截至 `"2026-08"`。
2. raw GitHub URL 不能展示私有仓库内容；如果未来要将 photos 再切到私有存储，必须先提供可匿名读取的代理/CDN 前缀，不能只改 `upload.repository`。
3. `05_photos-update.py` 更新的是 photos 仓库内的月度 JSON，而非向图片仓库上传新图片；它必须有读取配置指定图片仓库的权限和写入 photos 的权限。
4. `04_convert-blog.py` 的 Git Data API 批量提交现已接收配置分支参数；不可恢复硬编码默认 `master/main` 的旧行为。
5. 发布前后均应重做凭据扫描，确保 `.env`、日志、临时文件、`__pycache__`、用户文章与图片不进入 ZIP 或 GitHub 归档。
