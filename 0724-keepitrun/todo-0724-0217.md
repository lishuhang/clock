### 最终插件策略（v1.16, commit `f8eeb51`）

使用 **`:post_render` hook** 修改最终 HTML 输出，处理三类 URL：

1. **相对路径**: `src="/YYYY/..."` → `src="https://lishuhang.me/img/YYYY/..."`
   - 来源: markdown `![](...)` 被 kramdown 转换
   - 匹配属性: `src`, `data-original`, `srcset`, `data-src`, `data-lazy`

2. **绝对 URL（缺少 /img/）**: `https://lishuhang.me/YYYY/...` → `https://lishuhang.me/img/YYYY/...`
   - 来源: layout 的 `absolute_url` 过滤器处理 `page.image`
   - 使用 negative lookahead `(?!img/|assets/|posts/|page/)` 跳过非图片路径

3. **weserv.nl 代理 URL（URL-encoded）**: `lishuhang.me%2F2026%2F...` → `lishuhang.me%2Fimg%2F2026%2F...`
   - 来源: layout 用 weserv.nl 代理封面图: `src="https://images.weserv.nl/?url=https%3A%2F%2Flishuhang.me%2F2026%2F..."`

### 关键踩坑总结

1. **Generator 修改 `post.content` 不可靠**: 即使日志显示 rewrite 成功，Jekyll 4 渲染器可能在后续步骤重新读取内容，导致修改丢失。**改用 `:post_render` hook 修改 `post.output`（最终 HTML）才可靠。**

2. **Ruby `next` 在 `gsub` block 中有问题**: `next md[0] if condition` 语法在 `gsub` block 中会导致 rewrite 计数正确但实际 output 不变。**改用 regex negative lookahead 在 regex 层面跳过匹配，避免在 block 内使用 `next`。**

3. **封面图与内容图路径不同**: 
   - 内容图: markdown `![](...)` → kramdown → `<img src="/YYYY/...">` (相对路径)
   - 封面图: `page.image` (front matter) → layout `absolute_url` → `<img src="https://lishuhang.me/YYYY/...">` (绝对 URL)
   - weserv 代理: layout 进一步包装为 `https://images.weserv.nl/?url=https%3A%2F%2Flishuhang.me%2F2026%2F...` (URL-encoded)
   - **三种格式都需要不同的 regex 处理。**

4. **GitHub Pages CDN 缓存**: 构建成功后，CDN 可能需要 1-2 分钟才反映新内容。调试时需要用 `?cb=$(date +%s)` 或 `Cache-Control: no-cache` header 绕过缓存。

5. **`:pre_render` hook 注册顺序**: gem 插件（如 jekyll-seo-tag）在 `_plugins/` 目录之前加载，所以它们的 `:pre_render` hook 先注册、先运行。如果我们的 hook 需要 seo-tag 之前运行，不能用 `:pre_render`，应该用 Generator（priority :high）或 `:post_init`。
