## 1. 本次完成的工作（增量）

### 1.1 v0.1.0 → v0.1.1 修复

#### 修复 1：B站封面上传
- **问题**：v0.1.0 用 file chooser 方式（`expect_file_chooser`）超时 10 秒失败
- **原因**：B站"添加主封面"按钮点击后不触发原生 filechooser 事件（B站用自定义上传组件）
- **修复**：保留 file chooser 尝试，但 fallback 到直接找 `.cover-upload input[type=file]` 并 `set_input_files`
- **实测**：✅ 封面上传成功，VLM 确认封面缩略图可见（蓝色背景图 + 4:3 和 16:9 预览）

#### 修复 2：B站简介填写
- **问题**：v0.1.0 所有 textarea selector 都不对
- **原因**：B站简介用 **Quill 富文本编辑器**，不是普通 `<textarea>`，而是 `<div class="ql-editor" contenteditable="true">`
- **修复**：增加 selector `.ql-editor[contenteditable=true]`，用 `page.type()` 输入
- **实测**：✅ 简介填写成功

#### 修复 3：B站分区选择
- **问题**：v0.1.0 找不到分区选择器，把 `.bcc-select`（创作声明）和 `.category-item`（标签推荐）误认为分区
- **原因**：从 HTML 快照分析发现 B站**默认会根据视频内容预选分区**，selector 是 `.select-item-cont-inserted`
- **修复**：策略改为"检查 `.select-item-cont-inserted` 是否存在；存在就用默认，不存在才点 `.select-controller` 选第一个"
- **实测**：✅ 分区"科技数码"被正确识别（B站默认推荐）

#### 修复 4：B站存草稿按钮
- **问题**：v0.1.0 所有 button selector 都不对，"no save draft button found"
- **原因**：从 HTML 快照分析，B站存草稿按钮是 `<span class="submit-draft" data-reporter-id="105">存草稿</span>`，不是 `<button>`
- **修复**：
  1. 增加 selector `.submit-draft`、`span.submit-draft`、`[data-reporter-id='105']`
  2. 不检查 `is_visible()`（span 可能被覆盖但可点击）
  3. 先试 Playwright `el.click()`，失败 fallback 到 JavaScript `el.evaluate("el => el.click()")`
  4. 最后兜底 `page.click("text=存草稿")`
- **实测**：✅ 草稿保存成功，URL 跳转到 `upload-manager/article?group=draft`（草稿箱列表页）
- **VLM 确认**：草稿箱显示 2 条草稿（v0.1.0 + v0.1.1 各 1 条）

## 2. 踩坑与突出问题（增量，下一个 agent 必读）

### 5.12 B站富文本编辑器
- B站简介用 **Quill** 富文本编辑器（`.ql-editor[contenteditable=true]`），不是普通 textarea
- 用 `page.type()` 输入，不能用 `page.fill()`
- 其他平台（如微博、小红书）也可能用富文本编辑器，adapter 实现时要加 `.ql-editor` 等 selector

### 5.13 B站默认分区预选
- B站会根据视频文件内容**自动推荐分区**，已选中状态 class 是 `.select-item-cont-inserted`
- 不需要 agent 强制选分区，除非用户指定
- 其他平台也可能有类似预选机制

### 5.14 B站存草稿按钮是 span 不是 button
- B站存草稿按钮是 `<span class="submit-draft" data-reporter-id="105">`
- Playwright 的 `is_visible()` 对 span 可能返回 false（被其他元素覆盖），但实际可点击
- 解决：不检查 is_visible，直接尝试 click，失败用 JavaScript `el.click()` 兜底

### 5.15 HTML 快照分析的威力
- v0.1.0 → v0.1.1 的 3 个关键修复（简介、分区、存草稿）**全部来自 HTML 快照 grep 分析**
- 流程：失败时 `save_html_snapshot()` → `grep -oE 'class="[^"]*"' page.html | sort -u` → 找正确 selector
- **下一个 agent 必须保留这个机制**：每个失败步骤都保存 HTML 快照

### 5.16 VLM 验证截图的价值
- 用 `z-ai vision -p "..." -i screenshot.png -o output.json` 分析截图
- glm-5v-turbo 能准确识别：页面状态（列表/编辑）、登录态、按钮文字、表单内容、缩略图
- **符合用户诉求**："不要逼我截图"——agent 自己分析截图，编辑只需把 logs 文件夹打包发回

### 5.17 file chooser 不可靠
- B站自定义上传组件**不触发原生 filechooser 事件**
- `page.expect_file_chooser()` 会超时
- 替代方案：直接找 `input[type=file]` 并 `set_input_files()`
- 但要注意：input 可能是 hidden，需要 `wait_for_selector(state="attached")` 而非 `state="visible"`

### 5.18 测试超时问题
- B站完整流程约需 70-80 秒（含视频上传等待）
- bash 命令默认 120 秒超时，可能不够
- 用 `timeout 200 python3 script.py` 确保完成
- 或用 `nohup ... &` 后台运行
