# findings/04 — 持续性协议：防崩溃 / 防丢细节 / 防 token 狂烧

> 本文件回答用户的三个核心焦虑：①上下文过长沙盒崩溃如何保证工作延续；②todo/worklog 概括时如何不丢关键细节；③如何避免 token 狂烧原地打转。是本任务**流程设计**的规范文档。

## 1. 问题模型

```
会话A(长上下文) ──崩溃──> 会话B(空白上下文)
      │                        │
      │ 沙盒文件还在(可能)        │ 只能靠仓库里的文件恢复
      └──但上轮证明：沙盒文件会随回收丢失(A1坑)
```

失败模式对照：
1. **断档**：新会话不知道做到哪了 → 从头再来 → 重复劳动
2. **失真**：旧会话用自然语言"总结"进度 → 参数/报错/数字被抹掉 → 新会话按错误认知操作 → 失败 → 重新试错
3. **打转**：失败后不看原始报错就换姿势盲试 → 每次都烧一遍上下文 → 越试越接近崩溃

## 2. 机制设计（三层）

### 层1：state.json —— 单一事实来源（机器可读）

新会话**第一个**读它。字段固定：`phase`（当前阶段）/ `next_task`（下一条具体动作）/ `blocked_on`（等用户补给什么）/ `platform_status`（每平台主通路+已测程度）/ `environment`（环境速查）。**每完成一个任务必须更新**，哪怕只剩半句话也比没有强——崩溃前最后一件事就是把它写好推上去。

### 层2：worklog.md —— 追加式结构化日志（人/agent 可读）

条目模板（**字段固定，禁止自由发挥**）：

```markdown
## [W<三位序号>] <UTC时间戳> | task=<动词短语> | status=OK|FAIL|PARTIAL
- cmd: <原样命令，可直接复制重跑>
- raw: logs/<文件名>          ← 全文证据，永远给指针
- key_facts (verbatim):        ← ≤5行，逐字摘录原始输出的关键行
  - `<一行原文，数字报错一字不改>`
- conclusion: <一句话，只写本条证据支持的结论>
- next: <下一步是什么，或"见 state.json">
```

**为什么能防失真**：key_facts 是**复制不是转述**（verbatim 是硬规则）；需要更多细节时顺着 raw 指针去 logs/ 看全文，而不是相信任何人的概括。

**为什么能防打转**：每条都带可重跑的 `cmd`。同一 task 想再试时，先看旧条目的 verbatim 报错——如果报错没变，**重跑也不会变**（尤其 bot-check 类，A5 坑），直接换通路。

### 层3：logs/ + tools/ —— 证据与可执行资产

- 一切命令的原始输出落 `logs/<task>_<序号>.txt`；worklog 只存指针
- 一切探针/测试脚本落 `tools/`，**入 GitHub**（A1 坑的解药）
- 脚本设计规范：输出自我压缩（≤20 行关键信息）；退出码即结论；幂等可重跑

## 3. 恢复协议（RESUME.md 的执行摘要）

新会话固定动作链（目标 ≤3 分钟、≤5k token 恢复现场）：
```
读 state.json → tail -60 worklog.md → 读 findings/01 矩阵 → 执行 next_task
```
**禁止**：从头读 worklog 全史 / 通读 findings 全部 / 重新跑已完成的探针（环境事实直接信 findings/00，除非怀疑环境变了——重跑 tools/env_probe.sh + net_probe.sh 只要 1 分钟，先跑再信）。

## 4. 防 token 狂烧守则

1. **能用脚本做的绝不用模型做**：探测/解析/批量/校验全部脚本化；模型只做决策和写文档
2. **长输出永远不进上下文**：脚本里就 `grep/head` 压缩好；禁止 `cat` 大文件、禁止把网页全文粘进 worklog
3. **失败处理固定三步**：`tail -30 logs/<id>` → 对照 pitfalls → 换通路。禁止原地重试超过 1 次
4. **搜索结果只落 URL + 一句结论**，不整段搬运
5. **下载类操作全部 `--simulate`/`--dump-json` 先行**，确认通路再实下，避免大文件反复下
6. 每平台测试脚本独立（`tools/test_<platform>.sh`），输出一行结构化结果：`<platform> | OK/FAIL | <方法> | <关键证据一行>`

## 5. 保活（keep-alive）策略

| 对象 | 策略 |
|---|---|
| 沙盒进程 | 无法保活（环境会回收）。对策=崩溃容忍：任务粒度切小，每步落盘+推送 |
| GitHub token | 已验证 5000 req/h；token 在 .secrets 不入库；泄露风险仅限沙盒本地 |
| 工具版本 | yt-dlp 类快变工具，**每次实抓轮开头先 `pip install -U yt-dlp gallery-dl`**（nsig 类坑多为版本旧） |
| 平台 cookie | 存 `.secrets/cookies/<platform>.txt`（Netscape 格式，不入库）；记录获取日期；失效特征（401/403/checkpoint）出现时先怀疑 cookie 过期，找用户换新，不盲试 |
| 增量备份 | 每任务一 commit（message=[Wxxx]+结果），**push 即备份**；本地 /home/z/my-project 仅是工作副本 |
