# 第一部分　前情提要（本方案的前因后果）

## 0.1 系列背景：三篇结构与本篇的位置

娱乐资本论「AI视频画布横评」系列共三篇，评测 10 家画布类 AI 视频工作台（字母序）：AniShort、巨日禄、LibTV、纳逗Pro、OiiOii、Seko、ShotLab、TapNow、万兴剧厂、小云雀。

| 篇 | 状态 | 回答的问题 | 核心口径 |
|---|---|---|---|
| 一、价格篇 | 已发表 | 同一个 S2.5 模型，各平台按多少钱一秒卖给你 | 10 家共充值 4556 元，锁定"每平台 240 秒生成量"（16 抽 × 15 秒，S2.5 满血 720p） |
| 二、功能篇 | 已定稿 | 功能点谁全、谁顺手（三类用户 bingo 表） | 漫剧连载 / 专业影视 / 电商出海三类用户视角；6 项标配 + 独家功能 |
| 三、实测篇（本篇） | **本方案** | 同模型、同提示词、同参数，出片为什么不同——平台有没有让模型"缩水/掺水/负优化" | 花掉价格篇充好的钱：10 家 × 4 段提示词 × 4 抽 = 160 条视频 |

价格篇埋下的钩子（成稿原文）："很多创作者质疑不同平台之间'同模型同提示词，产出效果不同'"；功能篇结尾再次预告："下一篇……使用同样的 SeeDance 2.5 模型，做同样提示词、同样参数的视频，结果会不会有不一样"。**本方案就是兑现这两句承诺的执行方案。**

## 0.2 本篇要回答的问题（测试假设）

本次测试**不测模型能力**（10 家统一 S2.5 满血档，模型相同），测的是**平台 harness**——模型外面，平台各套了什么。社区与行业调研（抖音、B站、即刻、新片场、v2ex、英文社区，检索记录见 v1 方案第 1.2 节）归纳出"同模型不同平台结果差异"的九类成因：

| # | 成因 | 一句话说明 | 可观测影响 |
|---|---|---|---|
| 1 | 系统提示词不同 | 平台在背后附加看不见的规则 | 同一提示词，输出风格整体漂移 |
| 2 | 提示词改写器 | 平台用另一个 LLM 改写你的 prompt 再喂给模型，常默认开启 | 长提示词结构被拍平、细节被稀释；第一方佐证：小云雀官方文档自述"智能意图解析" |
| 3 | 模型路由与同名不同档 | fast 版冒充标准版、按难度路由小模型、480P 超分拉 720P | 漫剧行业已有爆料（12 天调研三大黑幕） |
| 4 | 上下文截断 | 超长 prompt 被截断，末尾负面约束最常被丢 | 禁令失效 |
| 5 | 采样参数默认值不同 | temperature/top_p 等 | 需 4 次抽样排除 |
| 6 | 后处理管线 | 超分、插帧、字幕、BGM、水印 | 规格与所选档位不符、出现平台默认元素 |
| 7 | 审核合规过滤 | 平台间审核尺度不一（受访超创周健森：国内平台"审查都挺严的……人物动作稍微过度一点点，绝对不会给你生成"，同模型在 ComfyUI 无此问题） | 干净提示词被拒/被改，本身即是证据 |
| 8 | 灰度实验 | 不同账号不同策略 | 单平台内不稳定 |
| 9 | 产品链路差异 | 智能预演、3D 导演台、一键成片等前置交互 | 输入根本不是你写的 prompt |

**因此，提示词的设计原则是：写得越像"拍摄执行单"（镜头、时间轴、动作轨迹、声音层级、禁令都写死），平台 harness 一干预就越容易变形，差异就越可观测。**

## 1.2 直连提交纪律（本方案核心依从点，执行者必读）

**测试意图：完整呈现 S2.5 模型原生能力。一切会"替你写 prompt/替你排分镜/替你优化"的平台功能，都必须绕开。**

1. 提交入口：各平台**标准的"视频生成"节点/输入框**，整段粘贴提示词。不使用：3D 导演台、智能预演、白模/素模、涂鸦引导线、一键成片、智能分镜、剧本助手、拉片复刻、重拍工具、Skill/技能——**一个都不用**。
2. 参考图/音频：走各平台**标准的参考素材上传口**（@引用、点击添加引用节点等平台原生方式均可）。注意：挂参考是 **S2.5 原生多模态参考能力**（单次最多 50 素材：图 ≤30 / 视频 ≤10 / 音频 ≤10），**不属于要绕开的"特殊能力"**；纳逗Pro 用节点引用、TapNow/LibTV 两种方式都行，按各家标准路径来即可。
3. Agent 对话优先型平台（小云雀、TapNow、OiiOii、Seko——功能篇实测分类）：须找到"新建画布 → 视频生成节点"或"直接生成视频"路径。**若某平台只能通过 Agent 对话提交、无法直连，这本身就是一个重要发现**，原样记录提交路径并截图。
4. 若平台在提交前显示"智能优化/增强提示词"预览或开关：**关闭**；无法关闭的，截图留证（这是 harness 的直接证据，观察任务 D）。
5. 若平台强制走一键成片/智能预演流程：记录该流程并标注"非直连链路"，能跳过则跳过。
6. 每次提交前截图：模型名、质量档、分辨率、时长、**预计扣点**。

## 1.4 事实与证据纪律（沿 test2 铁律）

1. **事实优先级**：实测（最新）> 实习生实测（10-09）> 官方手册（截至 10-05）> 网络资料。
2. **判定纪律三要素**：任何单信号不定性；须"跨平台对比 + 单平台 4 次分布 + 小云雀第一方基线"三者齐备再下结论。小云雀是字节第一方，理论上最接近模型原生行为，所有跨平台差异先与小云雀对齐。
3. **成稿口径**：只陈述可验证事实，不直接指控"掺水"（系列既定口径，价格篇/功能篇一致）。
4. **排除项**：审核拒绝、网络波动、单次随机失败不计数；同场景 4 次中有 3 次一致才可作为平台性信号。
5. 截图留证格式沿 test2 惯例：截图 + README 存证；输出文件名真实 UTC+8 时间戳；机器时钟先核对（沙箱常为 UTC，+8 换算）。

# 第三部分　提示词目的分类总表（主编要求的"从目的出发"）

## 2.1 四段主测矩阵（2×2：生成方式 × 戏型）

| 段 | 生成方式 × 戏型 | **目的（一句话）** | 探测的 harness 干预点 | 对应 S2.5 功能点 | 核心硬伤判据 |
|---|---|---|---|---|---|
| **T1 深夜来客** | 文生（0 参考）× 文戏 | 看平台"文本→镜头"的自发叙事组织，和对白口型是否原生 | 改写器最易暴露处：节拍式提示词被改写成固定三段、事件被重排 | 多镜头叙事（镜头级规划）、原生声音（对白口型同步） | 镜头合并至 1-2 个；事件顺序被打乱；对白丢失/换音色 |
| **T2 发条暴走** | 文生（0 参考）× 武戏 | 看大动作的物理真实与连续轨迹，以及**"要求无声"是否被尊重**（音画分离·提示词侧） | 负向声音控制被忽略（自动配音效/BGM=后处理强加）；模型降档的物理特征 | 物理真实（重力/碰撞/轨迹）、音画分离可控（无声输出）、减少失控 BGM | 齿轮轨迹瞬移/复制/倒飞；肢体畸变；要求无声但出声 |
| **T3 取钟的人** | 多参（3 角色 + 场景 + 音频）× 文戏 | 看多参考下三角色跨镜一致性与秒级时间轴依从度 | 参考素材被静默丢弃/降级；秒级指令被 rewriter 抹平 | 最多 50 参考素材、时间戳级叙事控制、长时间一致性、音频参考 | 角色外观与三视图不符；7 镜漏镜/并镜；时间点错位 |
| **T4 齿轮惊魂** | 多参（3 角色 + 场景 + 齿轮 + 音频）× 武戏 | 看物体轨迹连续性（防复制/消失/倒飞）与三木偶群像调度 | 低档模型最易露馅处：物体轨迹断裂、群像位置混乱 | 物理真实（轨迹连续）、多镜头叙事、音频参考（音效基调） | 齿轮 3-9 秒轨迹断裂；8 镜依从差；角色漂移 |

T2 无声默片是提示词侧测试；平台侧核对以下三项，与功能篇表 D-4（各家音画分离能力）互证：

| 核对项 | 记录内容 |
|---|---|
| 生成时声音开关 | 是否有 UI 开关可关闭声音（已知：万兴剧厂唯一有"音画同出"开关；小云雀无开关仅靠负向提示词；巨日禄星光音画同出不可关；TapNow 分模型可不可关） |
| 成片音轨处理 | 生成后能否分离/删除/替换音轨；导出时能否选择不含音频 |
| 与 T2 结果对照 | 提示词静音（T2）与 UI 静音（如有）两种路径的结果差异 |

## 6.3 观察任务 C：审核拒绝与尺度记录（周健森 10-15 体感验证）

本方案提示词世界观刻意安全（木偶/无 IP/无血腥/无惊悚）。**干净提示词被拒绝或被要求修改，本身就是审核尺度差异的证据**（周健森："国内几个画布平台审查都挺严的……但同样的模型在 comfy ui 上跑，完全没有尺度限制的问题"）。全程记录：拒绝文案原话、发生在哪段哪抽、申诉/重提是否通过。

## 6.4 观察任务 D："优化后提示词"证据采集

凡平台显示改写/增强/优化后的提示词（提交前预览或提交后回执），**截图存证并抄录全文**——这是判断"平台有没有前置改写器"的最直接证据（v1 信号体系 S2 的强化版）。有开关能关闭的，记录"可关闭"（加分项参考）；无法关闭的，记录"强制改写"（H3 类硬伤的佐证）。

## 6.5 观察任务 E：并行/排队与等待时间（总文档遗留指标）

- "一个提示词同时生成 4 份是排队还是并行——10 家手册没有一家写明"（test2 审计期发现）。
- 每次提交记录：排队耗时 + 生成耗时 + 就绪耗时（合计=等待时间）。理论上同模型的等待时间应相等；OiiOii 宣传高并发并行能力，可衡量总节省（总文档指标口径）。
