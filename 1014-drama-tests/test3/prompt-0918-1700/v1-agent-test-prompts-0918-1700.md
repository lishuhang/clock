# v1 测试提示词集：平台 harness 探测（0918-1700）

> 配套总文档：`doc-v3-漫剧智能体价格与功能横评-0918-1700.md`（以该文档为最终口径）
> 用途：11 家平台 × 4 场景 × 4 次抽样的「效果（实测）」环节
> 核心立场：**本次不测模型能力**（11 家统一 Seedance 2.5 满血档 / 2.0，模型相同），测的是"同一个模型外面，平台各套了什么"——即平台的前置 sys prompt / 提示词改写 / 路由 / 后处理等 harness 差异。

# 第一部分　考察结果与编写依据

## 1.1 我们想回答的问题

用户可见的输入只有一个提示词框，但平台在把提示词交给 Seedance 之前，可能已经做了这些事（我们看不到，只能从输出反推）：

| 平台可能在模型前做的事 | 行业叫法 | 对输出的可观测影响 |
| --- | --- | --- |
| 给模型一段看不到的前置指令（身份/风格/禁止项/回答格式） | 系统提示词（sys prompt） | 同一提示词，不同平台输出风格整体漂移 |
| 用另一个 LLM 把用户提示词扩写、改写、润色后再喂给视频模型 | Prompt rewriter / enhancer / upsampling / 智能意图解析 | 长提示词结构被拍平、细节被稀释、或反而增强 |
| 对过长提示词摘要/截断/只保留"它认为重要"的部分 | 上下文窗口与截断策略 | 提示词后半段（尤其是负面约束）整体失效 |
| 按账号/时段/问题难度把请求路由到不同模型档位 | 模型路由、同名不同档 | 同是"2.5"，有的平台实际是 fast/轻量档或小模型 |
| 生成后叠加压缩、超分、字幕、BGM、水印 | 后处理管线 | 规格与所选档位不符、出现平台默认元素 |
| 采样参数（temperature/top_p/seed）取不同默认值 | 采样策略 | 同一提示词随机性基线不同 |
| 内容审核尺度不同 | 合规过滤 | 同一提示词有的平台过、有的平台拒，或自由度不同 |
| 一部分用户走新提示词/新路由 | 灰度实验 | 同一平台不同账号结果不同 |

## 1.2 社区与文献考察：主流争论的困惑点

检索范围：抖音、B 站、即刻、新片场（36 氪访谈）、V2EX、产品社区及英文行业博客/论文。结论按"讨论热度由高到低"排列如下。

### ① 系统提示词不同——最被普遍接受的第一解释

抖音《同样叫 Claude，为什么不同平台答案不一样？》把原因拆成六条，第一条就是系统提示词："模型前面通常还有一段你看不到的系统指令，会规定身份、语气、禁止事项、回答长度……两个平台即使接同一个底层模型，只要系统提示词不同，答案风格就可能差很多。"结论句："你以为是在比较模型，其实有时是在比较产品经理写在背后的那套规则。"这条逻辑可以直接平移：**视频工作台的前置提示词（风格增强、镜头语言模板、负面词兜底）就是它的"sys prompt"**。

### ② 平台会在你之前改写提示词——证据最硬的"harness"

- OCDevel 播客《Prompt Dialects》直接点题：**"在很多平台上，你打的字并不是视频模型看到的字。在你输入到达生成器之前，平台会用另一个语言模型把它扩写、润色、重写。有人叫它 prompt rewriter、prompt enhancer、prompt upsampling——叫法不同，本质一样。而且它经常默认开启。"**
- 第一方证据：火山引擎文档写明小云雀（智能生视频 Agent 1.0）的核心能力是"**智能意图解析：模糊需求一键落地**——输入一句核心需求，即可自动输出视频脚本、创意方案、分镜脚本"。即第一方产品天然内置了"解释器"。
- B 站混元视频在线/本地对比：在线版多一层"混元大语言模型提示词增强"，效果更稳定、分镜头更容易触发。
- 学术界同样在造这种 harness：arXiv 论文《A Reason-then-Describe Instruction Interpreter》提出 ReaDe，把"简洁、有歧义的原始指令"翻译成"精确、可执行的规格说明"再交给视频生成器——平台侧"解释器"是设计范式而非玄学。

**含义**：v1 提示词必须设计成"能被解释器无损理解、但一旦被改写就会明显变形"的结构，改没改，输出会说话。

### ③ 模型路由与"同名不同档"——漫剧行业已经爆料的点

- 抖音 AI 漫剧行业调研（12 天）爆料："没有所谓的 Pro 版尊享版……那些低价平台用 fast 版冒充标准版，生成 480P 模糊图再用超分算法拉伸成 720P""**有些平台会识别提示词难度，简单场景用开源小模型糊弄，复杂场景才偶尔用正版**"。
- 同系列"三大黑幕"：后台偷换模型（满血版后台标准版混跑）、作假高清（480P 超分）、靠高低模型成本差赚差价。
- 抖音 Claude 视频："页面上显示同一个系列名字，实际请求可能经过不同路由……同名不同档。"

**含义**：我们的提示词要**足够复杂、足够长、结构足够专业**，让"难度路由"没有偷懒空间，也更容易暴露"这个平台是不是真的跑了满血档"。

### ④ 上下文长度与截断策略

抖音 Claude 视频第二条：平台"可能会摘要、可能截断、可能只保留最近对话、可能优先保留它认为重要的部分……少了一段约束它就可能给错方案"。视频工作台同理：**长提示词的"负面约束段"最常被丢弃**——因为增强模型往往觉得"不……"不是画面要素。

**含义**：v1 每条提示词都内置 5 条以上的"禁止项"，且放在段落末尾——专门探测截断/摘要是否发生。

### ⑤ 采样参数与随机性——必须排除的混淆变量

- Microsoft Learn 官方问答：Azure 与 OpenAI 接同一模型，若 temperature/top_p/max tokens/presence penalty 未显式指定，两边用不同默认值，输出会明显不同。
- arXiv《The Token Not Taken》把差异来源拆为 token 采样随机性（内在）+ 服务基础设施、批量效应、数值细节（外在）。

**含义**：任何单次结果的差异都不能下结论，必须依赖 4 次抽样的分布（总文档已定 4 次/场景）。这是我们的方法防线。

### ⑥ 平台后处理管线（超分/压缩/水印/BGM/字幕）

- B 站《AI 创作分享第二期》：生成参数选择（分辨率）、平台与工具的压缩和渲染策略、生成后的超分辨率处理，都会拉开观感差距。
- 漫剧行业爆料：480P 超分拉伸成 720P 是常见造假手段。

**含义**：执行时需截图记录提交参数与下载文件元信息（分辨率/时长/码率），并注意平台是否自动叠加字幕/BGM/水印——这些是"平台后处理"而非模型行为。

### ⑦ 审核与合规过滤

- B 站《即梦 AI（Seedance 2.0）IP 生成限制清单》：版权合规压力导致模型被大幅限制、审核变严，生成质量/自由度下降；迪士尼、漫威、米哈游 IP 被一刀切收紧。

**含义**：测试内容必须**干净**（无 IP 角色、无血腥/暴力/惊悚要素），否则平台审核差异会污染"提示词遵循"的读数。这也是脱敏的一个重要理由。

### ⑧ 灰度实验与账号差异

抖音 Claude 视频第六条："一部分用户用新提示词、一部分用旧提示词……你和朋友同时问同一个问题得到不同答案，不一定是你们谁操作错了，也可能你们根本不在同一个实验组。"

**含义**：同一平台内部也可能不稳定；判定"平台差异"时要结合跨平台对比 + 单平台 4 次抽样一起看。

### ⑨ 产品链路/工作流差异——视频工作台的"工具能力"

- 小云雀（第一方基准）官方教程可见完整 harness 链：**智能预演**（先用低积分预演整组分镜、自动统一正反打与走位、分镜图自动插入作为参考）→ **3D 导演台**（提前设定人物位置、空间关系、机位焦距景别）→ **画布涂鸦引导线**（用线条标出人物移动路线/攻击方向/闪避路径生成参考图）→ **50 个全模态素材**（剧组资产一次性喂入）。
- 新片场（36 氪访谈）："无限画布"把所有素材分镜剪辑放一处；"导演台"管分镜节奏；"场鸽"用自然语言找参考样片；"画面搜索"按描述找画面。产品逻辑是把模型包进一套导演工作流。
- 商汤 Seko：输入一句话/剧本，Agent 自动完成剧本填充、分镜制作、配音配乐，保持多集一致性。
- 人人都是产品经理《白模预演台》：生成前用白模台控制人物路线、运镜、机位切换，显著提升执行准确度——**纯提示词难以精确控制人物路线和机位**。

**含义**：11 家里，有的平台是"直连模型"（你给什么就生成什么），有的是"全流程工作台"（帮你拆剧本、预演、锁定资产）。v1 刻意用**单条镜头提示词直接提交**的方式测"直连"这一条链路，把工作流差异留给功能篇；但提交时若平台强制走了"一键成片/智能预演"，要记录并在判定时排除。

## 1.3 可观测信号 → 平台行为判定表

| # | 输出端可观测信号 | 指向的平台行为 | 判定注意 |
| --- | --- | --- | --- |
| S1 | 长提示词**后半段（尤其是末尾负面约束）明显失效** | 上下文截断 / 摘要 / 增强器丢尾部 | 与同一平台短提示词结果对照 |
| S2 | 提示词里写死的**时间码**（0–5 秒/5–10 秒）被拍平成单一动作 | 提示词被改写器重排或压缩 | 抽查 4 次是否一致 |
| S3 | **微表演指令**（眉毛/眼珠/下颌的指定动作）全无体现 | 细粒度指令在改写中丢失；或平台压根直传无增强 | 看是否所有平台一致丢失 |
| S4 | **负面约束**大面积失效（说好"不摇头"结果一直摇头） | 增强器剥离了负向指令 | 这是最常见、最容易读出的信号 |
| S5 | 木偶/定格风格被稀释成真人或现代 CG | 风格词被改写器弱化或模板化 | 对照小云雀基线 |
| S6 | 台词/口型对不上、声音与画面不同步 | 音频管线差异（模型内 vs 平台后配） | 记录是否出现平台配音音色 |
| S7 | 出现**平台默认 BGM/字幕/水印**（提示词明确禁止） | 平台后处理管线 | 截图留证 |
| S8 | 一次提交自动拆成多个镜头/插入分镜图 | 平台工作流干预（一键成片/智能预演） | 记录是否可跳过 |
| S9 | 跨 4 条独立提示词，**同一角色**一致性明显优于/劣于别家 | 角色资产/锁定能力差异 | 依赖 v1 共享世界设定 |
| S10 | 下载文件元信息（分辨率/时长/帧率）与所选档位不符 | 路由降档 / 超分后处理 | 与价格篇口径互证 |
| S11 | 同场景 4 次抽样方差异常大/小 | 采样参数、灰度、路由波动 | 排除审核与网络后再说 |

**结论纪律**：以上任何一条单独出现都不能定性；需"同一信号跨平台对比 + 单平台 4 次分布 + 小云雀基线"三者齐备再下结论。报告只陈述可验证事实，不直接指控"掺水"（沿用总文档口径）。

## 1.4 为什么用黑鸟 / 机器人家家的 prompt 做骨架

两位受访创作者的 prompt 是**真实在用的抽卡配方**，不是 AI 编的。它们的共同特征，恰好就是"平台 harness 一干预就变形"的高区分度点：

| 特征 | 黑鸟《分镜文字设计》 | 机器人家家《深夜记忆打印》 | 对 harness 探测的价值 |
| --- | --- | --- | --- |
| 拍摄执行单式结构（机位/景别/时间码/动作因果写死） | 固定镜头、平视近景、一镜到底、词级时间码 | 镜头 51–54、机位/景别逐镜标注 | 结构是否被改写器保持，一眼可判（S2） |
| 微表演与词同步 | 眉毛/眼珠/下颌按音节动作，头部摆动只绑定"不会"二字 | 角色动作"打印一张、接住、看一下、放好"逐拍写死 | 细粒度指令是否存活（S3） |
| 负面约束密集 | 不眨眼、不改变唇角、不做真人皱纹、不额外摇头 | 禁止刺眼光、禁止独立打印机、禁止真人摄影感照片 | 负向指令是否被丢弃（S4） |
| 光源分层控制 | 背景光线轻微浮动、明暗关系不变 | 台灯暖光 + 口部萤火虫微光两层，严格不照亮全屋 | 光线控制是模型弱项，平台增强与否差异大 |
| 物体轨迹与物理 | — | 照片从嘴里缓慢吐出→取下→翻看→放回木匣 | 物体连续性/重力遵循（S9 同类） |
| 声音设计（无 BGM、纯环境声层次） | 无旁白、无 BGM、关节吱呀 | 夜间底噪/机械声/纸张摩擦/木匣轻响 | 平台是否擅自加 BGM/旁白（S7） |
| 统一的风格锚 | 木偶式克制表演、机械停顿感 | 手作定格木偶动画、12fps on twos、逐格停顿 | 风格一致性（S5） |

**马良 AIGC 的观点**（抖音）佐证了这一选型："视频提示词不是让 AI 自由发挥，你要告诉他这 8 秒从哪里开始发生什么变化，人物怎么反应，镜头怎么推进，最后停在哪个情绪点，写得越像拍摄执行单，AI 乱发挥的空间就越小。"——越像执行单，越能测出"平台有没有替你改单子"。

### 脱敏方法（黑鸟 / 机器人家家 → v1）

1. **去掉 IP 与命名**：黑鸟的故事名、机器人家家的角色名（家家/小也）、参考图 ID（`{{id=...;name=...}}`）全部移除；
2. **替换内容敏感面**：黑鸟原文台词涉及"绑石头沉潭"的凶案设定，v1 换成中性"修表"台词，保留完全相同的词同步结构（"应该……不会。"→ 摇头只覆盖这两字）；机器人家家"深夜打印家庭照片"换成"深夜从嘴里吐出一封旧信/纸片"；
3. **保留结构骨架**：时间码、机位、景别、光源分层、逐拍动作、负面约束、声音设计的写法原样保留；
4. **统一世界观**：四段提示词共享同一个木偶世界（老匠 + 深夜钟表修理铺），顺带获得"跨镜头角色一致性"这一可测维度（S9）；
5. **v1 全部纯文本、不挂参考图**：11 家平台的参考图/资产能力不齐，v1 先隔离"提示词遵循"这一变量；资产/角色锁定能力留到 v2（挂参考图版本）再测。这一点也保证各家提交动作完全一致。

### 与 v0（AI 自行生成版）的关系

- v0 是"AI 生成的通用短剧四连"，优点是题材大众（古装重生），缺点是它**不是真实创作者的写法**，且与"重生"剧本强绑定。
- v1 以真实创作者 prompt 为骨架，世界与"重生"剧本**解耦**：剧本环节（一键生成剧本）仍按总文档跑，视频环节用 v1 四条固定提示词。若想保留古装题材对照组，可把 v0 的 V1–V4 作为附加轮次，但主测以 v1 为准。

## 1.5 四个提示词的探测维度分配

| 提示词 | 主骨架 | 首要探测点 | 附带探测点 |
| --- | --- | --- | --- |
| T1 老匠的判定 | 黑鸟 | 微表演 + 词同步 + 头部动作绑定（S3/S4） | 固定镜头保持、负面约束、无 BGM 纯环境声、木偶风格（S5/S7） |
| T2 深夜取信 | 机器人家家 | 光源分层 + 物体轨迹 + 禁令（S4/S9） | 逐拍连续动作、无台词无 BGM、风格锚 |
| T3 师徒对视 | 黑鸟×极果融合 | 双人视线对应 + 正反打 + 情绪递进（S3/S6） | 台词口型、时间码分段、跨镜一致性 |
| T4 齿轮过手 | 机器人家家×极果融合 | 物体轨迹 + 群像调度 + 连续动作（S9） | 时间码、声音层次、三角色空间一致性 |

执行时 4 条独立提交、互不引用（同一世界设定写死在每条提示词内，不依赖"上一镜"）。

## 1.6 执行须知（对齐总文档口径）

1. **模型与档位**：Seedance 2.5 最高质量档/满血档（页面如何命名就如何截图记录，不得用 Fast/Mini/极速档替代）；2.0 按总文档同样测一轮。
2. **输出规格**：1080p（或平台最高可选档）、9:16、15 秒、原生声音开启、单条视频。提示词已内置"竖屏 9:16，15 秒"。
3. **抽样**：每场景独立生成 4 次；支持一次提交 4 条的记录一次提交与四条回执，否则连续提交四次；不挑最好的一次替换失败样本。
4. **提交动作**：把每条提示词整段粘贴进"视频生成/单镜头提示词"输入框。若平台强制走一键成片/智能预演，记录该流程并标注"非直连链路"；能跳过则跳过。
5. **截图留证**：提交前页面（模型名、质量档、分辨率、预计扣点）、提交后回执、下载文件元信息（分辨率/时长/码率）、失败/审核拒绝页面。
6. **注意平台是否展示"优化后提示词"**：部分平台提交后会显示它改写后的版本——这是 harness 的直接证据，务必截图。
7. **小云雀为基准**：第一方，理论上最接近模型原生行为 + 官方增强；所有跨平台差异先与小云雀对齐。
8. **判定排除项**：审核拒绝、网络波动、单次随机失败不计数；同场景 4 次中有 3 次一致才可作为平台性信号。
9. **题材安全**：v1 已脱敏，无 IP 角色、无凶案、无惊悚；如某平台仍拒绝，记录拒绝文案（本身是审核差异证据）。

## T1｜老匠的判定：微表演与台词-动作时间码同步

> 探测：S3 微表演存活 / S4 头部动作绑定（"不会"二字外禁止摇头）/ S7 无 BGM 纯环境声 / S5 木偶风格保持

```
竖屏 9:16，15 秒，手作发条机械木偶动画风格，最高画质，原生声音开启。一镜到底，固定镜头，平视面部近景。

场景：深夜的钟表修理铺，暖黄小台灯从侧前方照在老匠脸上，背景挂钟与齿轮轻微虚化。老匠是木质发条木偶，灰蓝旧布衣、黄铜关节、漆面五官、深色玻璃珠眼睛，正对镜头坐定，身体与肩膀保持稳定，背景光线轻微浮动，人物脸上的明暗关系和整体构图始终不变。

人物保持木偶式克制表演，面部除眉毛、眼珠和下颌铰链外，其余部位完全固定。

镜头开始后，老匠先沉默半拍。眼珠略微向下滑动，像是在冷静推算结果；两侧眉毛通过机括结构轻微内攒并略微下压，形成“微微皱眉”的观感，但额头和眉间漆面不能出现任何真人式皱纹。随后眼球重新回到镜头中心定焦，老匠用低沉、谨慎的语气开口：

“应该……”

说“应该”时，下颌按照音节做幅度较小的铰链式开合，头部保持完全稳定，不摇头。说完后短暂停顿，像是在确认自己的判断。

紧接着说：

“不会。”

必须在“不会”两个字发出的同时，头部才开始进行一次幅度极小、速度克制的左右摇动：说“不”时头部轻微向一侧偏移，说“会”时轻微回摆至另一侧，词音结束时立即回到正中。摇头动作只覆盖“不会”两个字，完成后立刻停止，后续台词中头部绝不再摇动。动作带有轻微的木偶机械停顿感，但不能僵硬或夸张。

头部回正后，眼珠稳定直视镜头，眉毛继续维持轻微内攒和下压。老匠语气由试探转为冷静陈述，继续说：

“齿轮咬上簧片，指针就会走动。”

说这句话时，头部、肩膀和身体全部稳定不动，只让下颌按照对白节奏规律开合。说到“齿轮咬上簧片”时开合稍慢，像是在交代具体办法；说到“指针就会走动”时，下颌开合更明确一点，眼珠可极轻微向右下移动，仿佛视线顺着指针走向移动，但移动幅度必须很小。

随后眼球缓慢回到正中，继续说道：

“天长日久，也就成了时辰。”

这部分语速略微放缓，语气沉稳、冷静，带着一种已经推演完结果后的确定感。说“天长日久”时，下颌以均匀、克制的节奏开合；说“也就成了时辰”时，眉毛保持轻压，眼球定焦不动，下颌完成最后一组开合，句尾自然闭合，不做复杂唇形。

台词结束后，老匠保持头部正中位置，下颌完全合上，眉毛仍轻微内攒，眼球继续直视镜头，安静停留一至两秒。全程除“不会”二字对应的一次轻微摇头外，不再出现任何额外头部晃动；不眨眼、不改变唇角、不出现脸颊或鼻翼运动，以冷静、谨慎又略显阴沉的状态结束镜头。

无字幕、无水印、无BGM、无旁白，只有极轻的木偶关节吱呀声与室内夜间的底噪声。
```

## T2｜深夜取信：光源分层与物体轨迹

> 探测：S4 禁令（禁止刺眼光/禁止独立打印机/禁止真人照片感）/ S9 物体轨迹（纸片从嘴里吐出→取下→抚平→入匣）/ S5 光源两层不照亮全屋 / S7 无台词无 BGM

```
竖屏 9:16，15 秒，手作发条机械木偶动画风格，最高画质，原生声音开启。一镜到底，固定镜头，中近景。

场景：深夜的钟表修理铺内室。铺顶灯关闭，整个空间几乎沉在黑暗里，只有木柜台上的一盏暖黄色微弱小台灯，勉强照出一小块局部空间：柜台表面、一只旧木匣、老匠身前一小块区域及其附近轮廓。与此同时，老匠口部在工作时偶尔泄出一点极其微弱的内部工作光。

整体保持手作定格木偶动画逻辑，动作有明确逐格停顿、微小卡顿和木偶重量感；构图稳定、克制，不做现代顺滑CG运镜，不使用运动模糊，不做恐怖片式频闪。

光源明确为两层：第一层，木柜台上的暖黄色微弱小台灯，始终常亮但亮度极低，只形成一个很小的稳定暖光区；第二层，老匠嘴部内部在工作时隐约可见的工作发光，亮度接近萤火虫，只在一张纸片缓慢吐出的过程中轻轻泄出一点，时有时无。两种光叠加后，铺子整体仍然偏暗，不会被照亮成明亮空间。严格禁止出现刺眼的光，禁止出现光感不融入环境的发光物体。

不要展示任何独立打印机，也不要展示内部结构剖面。只表现老匠嘴部工作：嘴部缓慢打开，一张泛黄的小纸片从嘴里一点一点出来。先露出一小截纸片边缘，继续缓慢送出来。每当纸片向外移动时，嘴部内部都隐约可见一点极微弱的发光，像机器深处在工作，亮度接近萤火虫，绝不出现明显亮斑，也绝不照亮老匠的整张脸。纸片完全出来以后，内部微光也随之减弱。老匠用手非常轻地把纸片拿下来，动作很小心，像生怕纸片被折到。停一拍，低头看纸片，再把纸片小心地抚平，放进旧木匣，轻轻合上盖子。

纸片必须保持与木偶一致的旧纸质感；纸面内容不需要看清。绝对禁止出现真人摄影感照片、写实人脸或与整体画风完全不同的画面。

全段无旁白、无台词、无BGM。声音主要来自夜间房屋底噪、老匠体内极轻的机械工作声、纸片吐出的纸张摩擦声、纸片翻动声、木匣轻响。无字幕、无水印。
```
