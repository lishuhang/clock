## 四、新增踩坑与注意事项

### 坑 9：CSS `!important` 能覆盖内联 style，但不能覆盖内联 `!important`
- v2.20 模板的 `.chart-container` 内联 `style="width:900px;min-height:1080px;"` 没有 `!important`，所以 CSS `!important` 可以覆盖。
- 但如果模板将来改成 `style="min-height:1080px !important;"`，就必须修改内联 style 本身。
- **后续 agent 检查**：如果发现 override 不生效，先看模板的内联 style 是否带 `!important`。

### 坑 10：`.chart-body` 默认有 `flex:1 1 auto; min-height:400px;`
- v2.20 设计意图是让 chart-body 占满 .chart-container 的剩余空间（标题+body+footer 三段式）。
- 但当 .chart-container 改为 `height:auto` 后，flex:1 没有"剩余空间"可分配，min-height:400px 会强制 body 至少 400px 高，造成底部空白。
- **必须同时 override**：`.chart-body{ flex:0 1 auto !important; min-height:auto !important; }`。

### 坑 11：CSS `content:"\201C"` 引号在某些环境下乱码
- 在 Playwright/Chromium 渲染中文页面时，CSS `content:"\201C"` 和 `content:"\201D"` 可能被错误解码为 `)C` `)D`（即用户报告的乱码）。
- **修复方案**：放弃 CSS 伪元素，直接用 HTML 实体或 UTF-8 字符。本轮用 `<span class="qmark">"</span>`（注意是真实 Unicode 字符 U+201C/U+201D，不是 ASCII 引号）。

### 坑 12：VLM 数据结构需要 print 验证
- 遇到 SVG 内容缺失（如 polyline 不渲染）时，**先 print type(val)** 而不是直接报错重试。
- VLM 输出的 `data_points[*][1]` 可能是字符串、数字、或 list（双值时点数据）。
- 通用解析逻辑：
  ```python
  val = pt[1]
  if isinstance(val, list) and len(val) >= 2:
      v_init, v_curr = float(val[0]), float(val[1])
  else:
      v = float(str(val).replace('%','').strip())
  ```

### 坑 13：upload/ 目录有时为空（用户文件未传过来）
- 用户说"已上传 X 文件"，但 `/home/z/my-project/upload/` 可能为空。
- **下一个 agent 第一步**：先 `ls /home/z/my-project/upload/` 验证文件实际存在，不存在时立即告知用户重传，不要假设文件在某个隐藏路径。

### 坑 14：device_scale_factor=2 让 PNG 实际尺寸翻倍
- 截图脚本设 `device_scale_factor=2`，所以 900px 容器变成 1800px PNG。
- 这是高清截图，用于打印/海报合适。但若用于 1:1 视频引用（round2 步骤），需要重新评估是否需要降为 1x。
