## 四、新增踩坑与注意事项

### 坑 31：CSS `!important` 会阻止 animation forwards
- 初始状态用 `opacity:0 !important`，animation `forwards` 无法覆盖到 `opacity:1`
- **解决**：初始状态不用 `!important`，让 animation 的 `forwards` 能覆盖
- **后续 agent 注意**：animation 终态要用 `forwards`，初始状态不能加 `!important`

### 坑 32：Playwright 截图时机
- `page.goto` 后 CSS 动画立即开始，首帧可能已播放
- **解决**：用 `body.play` 类触发，goto 后先截首帧（纯白），再加 `.play` 类
- 这样首帧保证是纯白画布

### 坑 33：ffmpeg `filter_complex` 内存爆炸
- 用 `split+reverse+concat` 单命令处理 105 帧 1080×1080 时，ffmpeg 占用 1.8GB 内存
- **解决**：改用 3 步独立 ffmpeg 命令（entrance / static / exit），每步内存可控
- **后续 agent 注意**：大帧量视频处理用分步 ffmpeg，不要用复杂 filter_complex

### 坑 34：ffmpeg `-loop 1 -t 3` 生成 static 视频很慢
- 单帧循环 3s（90帧）的 static 视频用 `-loop 1` 很慢
- **解决**：用 `ultrafast` preset，配合 `-t 3` 限制时长

### 坑 35：bash 后台进程易被 session 关闭杀掉
- `nohup` + `&` 在 IM session 中不稳定，进程经常意外退出
- **解决**：改用前台逐张运行，每张用 `timeout 120` 限制
- 17 张总耗时约 10-15 分钟

### 坑 36：bash printf 在 heredoc 中易被截断
- `printf "file '...'\n"` 在某些 bash 上下文中被解析错误
- **解决**：改用多个 `echo` 命令写 concat.txt

## 五、动画设计原则（给步骤 7 的 v2.21c skill）

### 入场顺序（固定，所有图共用）
1. **logo**（右上角）：opacity 0→1，0.6s，delay 0s
2. **title**（左上角）：opacity 0→1，0.6s，delay 0.4s
3. **非图表主体**（图名、图例、坐标轴、表头）：opacity 0→1，0.6s，delay 0.8s
4. **图表主体**：特定动画，delay 1.2s

### 图表特定动画（复用，不重复造轮子）
| 图表类型 | 动画 | CSS |
|----------|------|-----|
| 饼图 | 顺时针扫描 | conic-gradient mask + @property |
| 柱状图 | 从底生长 | scaleY(0→1), transform-origin:bottom |
| 哑铃图 | 线生长+点淡入 | line scaleX + dots fadeIn |
| 热力图 | 行逐行淡入 | tr:nth-child stagger |
| 文字卡 | 上浮+淡入 | translateY(20px→0) + opacity |
| 散点 | 行逐行淡入 | row stagger fadeIn |

### 录屏规则
- HTML 只做入场，不做出场
- 录制入场（3.5s）+ 末帧静止3秒 + 倒放入场（3.5s）= 10s MP4
- 用 ffmpeg 3 步：entrance → static → exit(reverse) → concat
