## 一、用户原始 prompt

> 不对，比如第一部电影2012年就有了，那么从视频的开头到结尾，三个点要一直平缓地在图上移动，而后面才有的就动的快一点，但是在图上存续的时间里，他都是随着时间推移变化的，而不是好了就停留在图上。而且，图上每个电影每个色彩只有1个实心点而不是由一个空心点和一个实心点，因为早前空心点代表运动的起点和终点，但现在，这个点运动的全过程动画都可以展示出来了，所以就不用空心点代表移动起点了。
> round 3.8

### Agent 蒸馏回应

#### 核心改变 vs round3.7
1. **连续移动**：所有点的位置随时间持续变化，不是"出现后定格"
2. **只有实心点**：每电影每色只有 1 个实心点（无空心起点），动画展示全过程
3. **速度差异**：2012电影从 t=0 移动到 t=12（慢），2026电影从 t=10 移动到 t=12（快）

#### 动画逻辑（JS requestAnimationFrame）
- 10 部电影，每部有 appear_time（出现时间）和 TOTAL_DUR=12s（全部到达终点的时间）
- 任意时刻 t，某电影的进度 = (t - appear_time) / (TOTAL_DUR - appear_time)
- 点的 X 位置 = x_init + (x_curr - x_init) × 进度
- 轨迹线从 x_init 延伸到当前 X 位置
- 数值标签跟随点移动，实时更新百分比

#### 时间线（14s）
| 时间 | 事件 |
|------|------|
| 0-0.5s | 淡入（logo→title→SVG→图例） |
| 0s | 2012 电影出现，3 点开始从 init 缓慢移动 |
| 1.1s | 2015《杀破狼2》出现 |
| 2.2s | 2015《战狼》出现 |
| ... | 每 1.1s 出现一部 |
| 10s | 2026《镖人》出现（快速移动） |
| 12s | 全部 10 部到达终点位置 |
| 12.5s | 开始淡出 |
| 13.5s | 全白 |

#### VLM 验证
- t=0.5s：1行数据点（2012刚开始）✓
- t=6s：5行数据点在移动 ✓
- t=12s：全部10行到达终点，每行3个实心彩色点 ✓
- t=13s：淡出中 ✓
- t=13.5s：全白 ✓
